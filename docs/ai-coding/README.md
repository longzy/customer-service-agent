# AI Coding 协作规范

- 状态：草案
- 适用对象：Codex、Claude Code、Gemini CLI、GitHub Copilot 及其他可读取仓库的 AI Coding 工具
- 日期：2026-11-14

## 1. 核心原则

仓库是项目事实源，聊天只是协作界面。

新会话、压缩上下文或切换工具后，Agent 必须先恢复仓库状态，再决定下一步。任何只存在于上一段聊天中的结论，都不能作为继续开发的依据。

## 2. 文档职责

| 文件 | 职责 | 更新时机 |
|---|---|---|
| `AGENTS.md` | 启动路由、权威顺序和硬性边界 | 工作流或入口变化时 |
| `docs/CURRENT.md` | 当前阶段、完成项、进行中项、阻塞和下一步 | 每次有意义的任务结束前 |
| `docs/product/charter.md` | 产品定位、范围和非目标 | 产品范围批准后 |
| `docs/architecture/` | 总体架构和不变量 | 架构约束变化时 |
| `docs/adr/` | 架构上重要的决策及后果 | 做出长期决策时 |
| `docs/specs/` | 当前 Milestone 的可执行规格 | 里程碑需求或设计变化时 |
| `docs/handoffs/` | 跨会话、跨工具的详细接管记录 | 长暂停、切换工具或任务复杂时 |
| `docs/reviews/` | 历史评审和当时依据 | 原则上不修改 |

同一含义只保留一个权威位置。根指令文件使用指针，不复制详细规范。

## 3. 新会话恢复流程

### 第 1 步：读取入口

读取：

1. `AGENTS.md`。
2. `docs/ai-coding/README.md`。
3. `docs/CURRENT.md`。

完成标准：已知道项目阶段、当前 Milestone、允许范围、完成项、进行中项、阻塞项和下一步。

### 第 2 步：读取任务相关上下文

根据任务选择：

- 产品范围变化：读取产品宪章。
- 架构变化：读取总体架构、不变量和相关 ADR。
- 功能实现：读取当前 Spec、Acceptance 和 Tasks。
- 接管未完成任务：读取最新相关 handoff。
- 历史判断：读取初始评审，不把它当成现行规格。

完成标准：能够指出本任务对应的需求 ID、验收 ID 和架构约束。

### 第 3 步：核对仓库现实

检查文件、代码、测试和 Git 状态是否与 `CURRENT.md` 一致。

完成标准：识别“文档声称的状态”和“仓库实际状态”的差异。存在差异时先更新事实，不继续实现。

### 第 4 步：报告恢复结果

开始实质工作前，用简短清单报告：

- 当前阶段。
- 已完成。
- 进行中。
- 阻塞。
- 本任务下一步。

完成标准：用户能在不阅读旧聊天的情况下判断 Agent 是否理解正确。

## 4. 单个任务的执行闭环

### 4.1 定界

把任务映射到当前 Milestone、Requirement 和 Acceptance ID。

完成标准：

- 明确本次要改变什么。
- 明确本次不改变什么。
- 没有验收标准的业务实现任务保持未就绪状态。

### 4.2 设计

确认接口、状态、权限、失败路径和测试方式。

完成标准：实现者能说明输入、输出、状态转换、错误分类和验证方法。

### 4.3 实施

小步推进一个可验证闭环。业务代码、契约和调用方同步变化。

完成标准：变更范围没有超出当前任务；关键规则有确定性实现位置。

### 4.4 验证

运行适用的测试、类型检查、构建、Lint、场景评测或文档检查。

完成标准：

- 有实际命令和结果。
- 正常、拒绝、重复、异常和权限场景按适用范围覆盖。
- 不存在未报告的关键失败。

### 4.5 审查

对照 Requirement、Acceptance、ADR 和架构不变量审查差异。

完成标准：每个验收项都有实现或明确的未完成说明。

### 4.6 记录

更新 `docs/CURRENT.md`，并在本次任务结束时提交；`CURRENT.md` 的更新与本次变更进入同一次提交，不单独留待下次。发生以下任一情况时创建 handoff：

- 即将切换 AI Coding 工具。
- 任务会跨多个较长会话。
- 实现尚未完成但需要暂停。
- 做出影响后续工作的关键判断。
- 出现阻塞，需要其他人或另一个 Agent 接管。

完成标准：新的 Agent 只读仓库即可继续，不需要旧聊天。

## 5. `CURRENT.md` 更新规则

必须维护以下字段：

- 更新日期。
- 项目阶段。
- 当前状态。
- 当前 Milestone。
- 最近验证。
- 已完成。
- 进行中。
- 阻塞。
- 下一步。
- 待确认决策。

状态词只使用：

- `未开始`
- `草案`
- `等待评审`
- `已批准`
- `进行中`
- `阻塞`
- `已完成`
- `已暂停`

只有当实际命令成功执行后，才能把相关结果写入“最近验证”。不得用模型判断替代命令结果。

## 6. Handoff 规则

handoff 文件名使用：

```text
YYYY-MM-DD-简短主题.md
```

每份 handoff 至少包含：

- 本次目标。
- 已完成内容。
- 未完成内容。
- 关键决策及 ADR/Spec 链接。
- 已运行的验证和结果。
- 当前阻塞。
- 下一位 Agent 的准确下一步。
- 涉及文件。

handoff 是某次接管的快照；实时状态始终以 `CURRENT.md` 为准。

## 7. 变更控制

- 产品范围变化：更新产品宪章，并检查当前 Spec 是否仍有效。
- 长期架构变化：新增 ADR，保留旧决策和替代原因。
- 当前功能变化：更新 Spec、Acceptance 和 Tasks。
- 小修复：可直接执行，但仍需更新 `CURRENT.md`。
- 原始评审：保持原样；新结论写入现行文档或 ADR。

## 8. 工具切换

### 自动读取

支持 `AGENTS.md` 的工具应直接从其开始。

### 工具专属入口

仓库提供轻量适配文件：

- Claude Code：`CLAUDE.md`。
- Gemini CLI：`GEMINI.md`。

适配文件只负责指向 `AGENTS.md`，不维护第二套规则。

### 手动启动提示

如果工具不会自动读取任何项目指令，在首次消息中使用：

```text
请先读取仓库中的 AGENTS.md、docs/ai-coding/README.md 和 docs/CURRENT.md。
在修改任何文件前，用五项摘要确认：当前阶段、已完成、进行中、阻塞、下一步。
如果仓库状态与本次请求冲突，先指出冲突并等待确认。
```

完成标准：Agent 回复的五项摘要与仓库事实一致后，才允许继续。

## 9. 安全与决策边界

- 使用最小必要上下文，只加载与当前任务相关的文档。
- 不把密钥、令牌、真实用户隐私或生产数据写入仓库或 handoff。
- 对真实业务系统、不可逆操作、资金操作和权限模型变化保持人工决策。
- 需求、规格、ADR 与当前指令冲突时，先报告冲突。
