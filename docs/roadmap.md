# 路线图

> 2026-11-16 方向重置：目标改为“企业内部 AI 客服系统”。本文的 M1 消费者定位已归档为 M1-P 原型；新基线见 [企业化方向重置](initiatives/2026-11-16-enterprise-reset.md)。R0-1 完成前，不以本文旧用户/里程碑作为新开发依据。


## 阶段原则

- 每阶段交付一个可验证的业务闭环和对应评测集。
- 不以“模块开发完成”作为里程碑完成标准。
- 权限、幂等、审计和可观测性从 M1 建立，后续只增强。
- 真实业务系统在 Mock 契约稳定后再接入。

## M0 项目基线

交付：

- 原始评审归档。
- 产品宪章。
- 总体架构、不变量和技术决策。
- M1 需求、设计、任务和验收用例。

出口条件：

- 范围、非目标和 M1 状态语义无重大歧义。
- 规格和验收用例经过确认。

## M1 订单查询与未发货订单取消

验证：

- 多轮意图和订单澄清。
- 服务端数据授权。
- 确定性取消资格。
- 用户确认。
- 写操作幂等。
- 超时后的状态查询和恢复。
- 执行 Trace 和审计。

出口条件：

- M1 所有验收用例通过。
- 越权和重复操作均为 0。
- 正常、拒绝、异常和恢复场景有自动化证据。

## M2 退款申请

增加：

- 退款资格和金额规则。
- 支付和 OMS 状态语义。
- 人工审批阈值。
- 提交、受理、成功和失败的严格区分。

## M3 知识与售前导购

增加：

- FAQ 与商品静态知识 RAG。
- 实时库存和价格 API。
- 商品筛选和推荐理由。
- 知识依据评估。

## M4 人机协同

增加：

- 人工接管工作台。
- 完整任务上下文和待处理步骤。
- 工单、审批和质检。

## M5 渠道与可靠性扩展

增加：

- 第二渠道适配器。
- 故障注入、熔断和恢复增强。
- 多租户配置隔离增强。

## M6 企业治理与持续评估

增加：

- 多环境发布与模型版本对比。
- 成本、延迟和质量看板。
- 更完整的合规、审计和数据治理。

注意：M6 是治理能力增强，不表示安全、权限和审计到 M6 才开始建设。
