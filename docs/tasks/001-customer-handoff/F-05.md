## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：坐席用种子账号 `agent_1`/`agent_2` 登录工作台，获得 8h 绝对 session；刷新恢复登录；登出/过期 401，登录超限 429，非 agent 403，未领取/他人会话 404。
- 涉及层：后端 / 迁移 / 前端 / 契约（OpenAPI 前端类型）/ 工具链

- 本次改变：
  - 迁移 `0010_service_employee_auth`：新增 `service_employees`、`service_employee_sessions`（plan 3.2 字段；session 只存 token 哈希）。
  - `backend/platform/models.py`：`ServiceEmployee`、`ServiceEmployeeSession`。
  - `backend/identity/employee_sessions.py`：scrypt 校验、8h 绝对过期、登录轮换撤销同员工旧 session、登出撤销、`employee_login:{username}:{ip}` 5/15min 限速；角色必须为 `agent`。
  - `backend/identity/tokens.py`、`backend/identity/rate_limit.py`：抽出 token 哈希、UTC 时钟与固定窗口限速的共用实现；`customer_sessions` 保持原导出名与行为不变（F-01 测试不改）。
  - `backend/conversations/workspace_http.py`：`POST/DELETE /workspace/sessions`、`GET /workspace/session`、`GET /workspace/conversations/{id}`（本卡只做归属门禁与 `{id,status}` 最小响应）。
  - `backend/conversations/schemas.py`：员工/会话/最小会话响应模型；`backend/domain/errors.py` 新增 `FORBIDDEN`（403 `无权访问`）。
  - `backend/api/main.py`：`M1_ENABLED` 时挂载 workspace 路由；`/workspace/` 的 422 统一封套。
  - `scripts/seed_demo.py`：幂等创建/重置 `agent_1`/`agent_2`（角色 `agent`，显示名“坐席 1/2”），沿用 `DEMO_PASSWORD`。
  - `apps/workspace`：新 Next app，`/login` 与 `/queue`；`/queue` 只做 8h session 门禁、坐席信息与登出入口（队列内容 F-06 接入）。
  - 工具链：`packages/contracts` 同时生成 `apps/workspace/lib/api-types.ts`；`check-api-types.sh` 校验两个前端；`verify.sh` 增加 workspace lint/format/typecheck/test；`dev.sh` 在 3001 启动工作台；CI 安装/构建 workspace；开发环境 Origin 白名单加 3001。
  - 快照：`tests/fixtures/db-schema-r0-2.json`、`openapi-r0-2.json` 按现有机制同步。
  - 测试：`tests/integration/workspace_support.py`、`tests/integration/test_workspace_auth_AC_34.py`、`apps/workspace/tests/*`。
- 本次不改变：
  - 客户登录/会话（F-01）语义；客户 cookie `csid` 与员工 cookie `esid` 完全独立。
  - 队列摘要/领取/接管（F-06~F-09）；`GET /workspace/conversations/{id}` 本卡不返回消息、AI 轨迹、交接单上下文。
  - 审计与安全事件（F-13）；本卡不写 `service_audit_events`。
  - 客户/员工自助注册、MFA、主管/管理员角色、OIDC/SSO。
  - 不新增自动分配、WebSocket/SSE；不接真实 OMS。

## 2. 任务级决策

### 2.1 需人类决策

无。员工账号、8h session、5/15min 限速、非 agent 403、越权 404 已由 brief AC-34 与 plan 3.3.2/5.1 批准；本卡只落实实现细节。

### 2.2 声明的 seam

| ID | 内部接口 | 为什么测试直接驱动它 |
|---|---|---|
| S-1 | `POST /workspace/sessions` | 员工登录、cookie 属性、401/422/429/403 |
| S-2 | `GET /workspace/session` | 刷新恢复；过期 401；登录后角色变更 403 |
| S-3 | `DELETE /workspace/sessions` | 撤销与幂等登出 |
| S-4 | `GET /workspace/conversations/{id}` | 未领取/他人/跨租户 404；本人已分配 200 |
| S-5 | `service_employee_sessions` | 8h 绝对过期、token 只存哈希、轮换撤销 |
| S-6 | `backend.identity.employee_sessions` 常量/函数 | TTL、cookie 名、限速窗口 |

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | “非 agent 403”发生在哪一层 | 合法凭据但角色非 `agent` 时 `POST /workspace/sessions` 返回 403 `FORBIDDEN` 且不创建 session；`GET /workspace/session` 每次解析也校验角色，角色变更后立即 403 | AC-34 把 403 与登录结果并列；登录即拒绝最直接。解析层再校验是 INV-17 的纵深防御 | 小 |
| D-2 | plan API 表没有 `GET /workspace/session` | 增加只读 `GET /workspace/session`，返回员工与 `expires_at` | 刷新 `/queue` 必须能恢复 8h session；与客户 `GET /customer/session` 对称，纯增量 | 小 |
| D-3 | 本卡的 `GET /workspace/conversations/{id}` 响应 | 只返回 `{id, status}`；查询条件 `tenant_id + assigned_employee_id=me`，其余一律 404；完整上下文由 F-08 增量扩展 | 让 AC-34 的 404 可判定，又不越界实现 F-08 的上下文展示 | 小 |
| D-4 | 员工 cookie | 名 `esid`；`HttpOnly`、`SameSite=Lax`、生产 `Secure`、`Max-Age=8h`、`Path=/` | 与 plan 3.3.2 一致；与客户 cookie 分离，互不提升权限 | 小 |
| D-5 | 登录轮换范围 | 撤销该员工全部未撤销 session | plan 明确“登录轮换撤销同员工旧 session” | 小 |
| D-6 | 员工登录限速 | 复用固定窗口实现；key `employee_login:{username 小写}:{ip}`，5 次/15min，第 6 次起 429 + `Retry-After` | plan 5.1 指定员工登录限速；与客户登录策略对称 | 小 |
| D-7 | 员工 session 是否记录 `last_seen_at` | 不记录 | plan 3.2 的员工 session 表没有该列；本卡无“最近活跃”需求 | 小 |
| D-8 | 角色取值 | 只认小写 `agent`；其余值一律 403；种子只建 agent | plan 3.2“M1 仅 agent”；测试直接播种 `supervisor` 验证 403 | 小 |
| D-9 | 工作台端口与页面范围 | 开发端口 3001，加入测试环境 Origin 白名单；`/queue` 本卡只展示坐席信息、登出与占位区 | 与客户 app 3000 分离；F-06 再填队列内容，避免伪造空队列接口 | 小 |
| D-10 | 共用 token/时钟/限速实现 | 抽到 `identity/tokens.py` 与 `identity/rate_limit.py`；`customer_sessions` 继续导出原名字，行为不变 | 避免员工/客户两套哈希与限速漂移；F-01 测试与 monkeypatch 点保持有效 | 小 |
| D-11 | 404 与 403 的区分 | 未登录 → 401；已登录 agent 访问非本人/跨租户/不存在会话 → 404；合法凭据非 agent → 403 | plan 5.1 越权矩阵：越权资源统一 404，角色不符 403 | 小 |
| D-12 | `M1_ENABLED=false` | workspace 路由与客户路由一起不挂载，返回 404 | 复用 plan 5.3 的回滚开关，不新增配置 | 小 |
| D-13 | 员工账号是否纳入现有 seed 的密码重置 | 是：与客户同用 `DEMO_PASSWORD`，重复执行重置密码并恢复 active/role | 演示数据可用 `make dev-reset` 一键回到干净起点 | 小 |
| D-14 | 快照与生成类型 | 迁移后同步 DB/OpenAPI 快照；workspace 类型只从 OpenAPI 生成，不手写 | 仓库既有门禁（AC-27/28、ADR-0007）要求 | 小 |
| D-15 | 员工表是否需要 `created_at` | 保留 `created_at`，与其它 `service_*` 表一致 | plan 3.2 列的是“关键列”，不是穷举；创建时间便于后续审计/排障 | 小 |
| D-16 | 并发登录语义 | 不定义并发登录的保留结果；每次成功登录都轮换该员工已有 session | AC-34 只要求登录轮换撤销旧 session，未要求并发登录都保留；避免为未批准需求加锁 | 小 |

### 2.4 判定表与失败矩阵

| AC | 主路径 | 非法输入 | 权限 | 下游故障 | 并发/重复 | 幂等 | 配置门禁 |
|---|---|---|---|---|---|---|---|
| AC-34 | `agent_1` 正确凭据 → 200 + `esid` + 8h；刷新 200 同一员工 | 空字段/未知字段 422；错误密码/未知账号统一 401 `AUTH_FAILED` | 未登录 401；非 agent 403；未领取/他人/跨租户会话 404 | 数据库异常 500 封套（既有 handler）；无外部依赖 | 重复登录轮换旧 session；并发登录未定义保留结果（D-16） | 登出幂等 204；同账号 5 次失败后 429 | `M1_ENABLED=false` 时不挂载；生产 cookie `Secure` |

## 7. 遗留（评审确认）

- 审计、登录/消息限速的安全事件与 401/403/429 审计统一由 F-13/AC-39 落地；本卡只做员工登录限速。
- `GET /workspace/conversations/{id}` 的完整上下文（客户、消息、AI 轨迹、交接单、待办）由 F-08 增量实现。
- 队列摘要与领取/接管（F-06~F-09）不在本卡；工作台 `/queue` 本卡只有会话门禁与占位区。
- 角色只有 `agent` 一种；主管/管理员视图不在 M1。
- `get_assigned_conversation` 以 `assigned_employee_id` 作为归属信号，未额外校验会话状态；转回 AI 时必须清除 assignment，由 F-12 收口。
- 员工登录限速与 F-01 一致，成功登录也计入窗口；AC-34 未区分成功/失败计数，本卡沿用既有固定窗口语义。
- `apps/workspace/lib/session.ts` 与 `apps/chat/lib/session.ts` 同构地手写 `ErrorBody` 形状；ADR-0007 的“只做生成类型别名”在 F-01 已是既有例外，抽公共 client 登记为后续技术债。
- 本卡只按需复用了 chat 的登录/容器样式，未引入共享 design token；CSS 统一仍是 M1 技术债。
