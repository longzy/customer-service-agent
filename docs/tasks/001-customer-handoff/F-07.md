## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：两个坐席并发领取同一交接单时只有一个成功（进入该会话），另一个看到 409 `CLAIM_CONFLICT`；领取成功后该单从队列消失，跨租户/不存在 404，不发生自动分配。
- 涉及层：后端 / 前端 / 契约（OpenAPI 前端类型）

- 本次改变：
  - `backend/conversations/workspace_conversations.py`：新增 `ClaimedHandoff`、`ClaimConflictError`、`HandoffClosedError` 与 `claim_handoff`；先按租户读交接单区分 404/409，再用 `UPDATE ... WHERE status='QUEUED' RETURNING id` 条件领取，同事务把会话改为 `CLAIMED` 并写 `assigned_employee_id`。
  - `backend/domain/errors.py`：新增 `CLAIM_CONFLICT`（409、不可重试、对用户可见）。
  - `backend/api/workspace_schemas.py`：新增 `WorkspaceClaimResponse`（`handoff_id`、`conversation_id`、`status`）。
  - `backend/api/workspace_routes.py`：`POST /workspace/queue/{handoff_id}/claim`；复用 `CurrentEmployee` 做 401/403，404/409 走错误封套，成功 commit。
  - `apps/workspace/lib/queue.ts`：新增 `claimHandoff()`。
  - `apps/workspace/components/QueueGate.tsx`：每项加“领取”按钮；成功跳转会话页；409 提示“该会话已被其他坐席领取”并刷新队列；404 提示并刷新。
  - `apps/workspace/app/conversations/[id]/page.tsx`、`apps/workspace/components/ConversationGate.tsx`：领取后的最小会话入口（只读会话状态与返回队列；上下文/接管由 F-08 扩展）。
  - `apps/workspace/app/globals.css`：领取按钮、会话页与冲突提示样式。
  - `tests/integration/test_workspace_claim_AC_35.py`：领取成功、并发、409、404、权限、已关闭、无自动分配的集成用例。
  - `apps/workspace/tests/QueueGate.test.tsx`、`apps/workspace/tests/ConversationGate.test.tsx`：领取成功跳转、冲突提示与刷新、404、会话入口门禁。
  - 契约：`packages/contracts/schemas/domain.json`（ErrorCode 枚举、ErrorEnvelope 条件、`x-error-specs`）与由 `scripts/gen_tool_openapi.py` 生成的 `packages/contracts/tools/openapi.json`；重新导出 `packages/contracts/openapi.json`、`tests/fixtures/openapi-r0-2.json` 与两个前端的 `api-types.ts`。
- 本次不改变：
  - 接管（F-08）、回复（F-10）、关闭/转回（F-11/F-12）；领取后不写“人工已接入”系统消息，客户侧状态文案不变。
  - 认证、session、RBAC 语义（F-05）；不新增角色，不改变 401/403 判定。
  - 数据模型与迁移：`service_handoffs` 已有 `claimed_by`/`claimed_at`/`version`，无新表/新列，`db-schema-r0-2.json` 不变。
  - 审计与限速（F-13）；领取不写 `service_audit_events`，审计统一在 F-13 补齐。
  - 自动分配、队列轮询/分页、WebSocket/SSE。
  - `GET /workspace/conversations/{id}` 的归属语义：仍只允许 `assigned_employee_id` 为本人且同租户；第二坐席查看 404 由 F-09 的用例覆盖。

|---|---|---|

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 领取响应体 | `{handoff_id, conversation_id, status}`，`status` 为会话状态 | 前端只需 `conversation_id` 跳转；`status` 让契约自证领取后为 `CLAIMED`；与 plan 3.3.5 的返回语义一致 | 小 |
| D-2 | 404 与 409 的判定顺序 | 先同租户读交接单：不存在/跨租户 → 404；`CLOSED` → 409 `CONVERSATION_CLOSED`；其他非 `QUEUED` → 409 `CLAIM_CONFLICT`；条件更新 0 行 → 409 `CLAIM_CONFLICT` | 错误码可区分“不存在/越权”与“被抢”；条件更新兜住读到 `QUEUED` 后的竞态 | 小 |
| D-3 | 并发控制 | 单条 `UPDATE service_handoffs SET status='CLAIMED', claimed_by=:me, claimed_at=:now, version=version+1, updated_at=:now WHERE id=:id AND tenant_id=:tenant AND status='QUEUED' RETURNING id` | Postgres 行锁 + Read Committed 重新评估条件，保证只有一个事务拿到行；不引入应用层锁或新约束 | 小 |
| D-4 | 会话状态同事务更新 | `UPDATE service_conversations SET status='CLAIMED', assigned_employee_id=:me, updated_at=:now WHERE id=:conversation_id AND tenant_id=:tenant AND status='QUEUED'`；0 行则回滚并 409 | plan 3.3.5 明确同事务；会话与交接单状态由 F-03 同事务维护，正常不会分歧 | 小 |
| D-5 | 审计 | 领取不写审计，留 F-13 | features F-13 统一挂 `handoff.claimed`；本卡不引入半套审计（plan 5.1） | 小 |
| D-6 | 领取后进入哪个页面 | `/conversations/{conversation_id}` 的最小只读页 | 满足 AC-35“进入会话”的可演示性；F-08 在同一页扩展接管与上下文，不改路由 | 小 |
| D-7 | 重复领取（同一坐席） | 409，不做幂等 200 | AC-35 要求“只有一个成功，另一个 409”；重复点击等同已被领取，前端刷新队列即可 | 小 |
| D-8 | 并发测试方式 | `ThreadPoolExecutor` + `Barrier`，每个线程独立 `TestClient`，打真实测试库 | 直接验证数据库条件更新；mock 或串行重放无法证明并发语义 | 中 |
| D-9 | 领取失败后的前端处理 | 409/404 显示提示并重新拉队列；401/403 回登录；500/网络错误显示“领取失败，请重试” | 服务端已过滤 `QUEUED`，刷新即可让被抢单消失；不伪造本地删除 | 小 |
| D-10 | 是否需要新迁移 | 不需要 | 领取列与部分唯一索引已在 0010 迁移中；`version` 只做原子自增 | 小 |
| D-11 | 是否要求 `Idempotency-Key` | 不要求 | 状态机 + 条件更新使重复请求安全地 409；M1 写幂等键统一在 003/安全硬化再评估 | 小 |
| D-12 | 领取后是否写系统消息 | 不写 | “正在接入人工/人工已接入”由接管的 F-08 负责（plan 3.4） | 小 |
