## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：多个客户已排队时，坐席打开工作台 `/queue` 能看到按 FIFO 排列的队列摘要（客户账号、等待秒数、原因、脱敏末条、订单数 0），且领取前看不到完整消息。
- 涉及层：后端 / 前端 / 契约（OpenAPI 前端类型）

- 本次改变：
  - `backend/conversations/workspace_conversations.py`：新增只读 `QueueItem` 与 `list_queued_handoffs`；同租户、`status='QUEUED'`、`ORDER BY created_at, id`；批量取每个会话最后一条客户消息并脱敏截断。
  - `backend/api/workspace_schemas.py`：`WorkspaceQueueItem`、`WorkspaceQueueResponse`（`{items: [...]}`）。
  - `backend/api/workspace_routes.py`：`GET /workspace/queue`；复用 `CurrentEmployee` 做 401/403 门禁；只读不提交事务。
  - `tests/integration/workspace_support.py`：新增 `seed_queued_handoff` 与固定时钟辅助所需的数据播种。
  - `tests/integration/test_workspace_queue_AC_35.py`：AC-35 的 FIFO、摘要、脱敏、租户隔离、空队列、权限、无副作用用例。
  - `apps/workspace/lib/queue.ts`：从 OpenAPI 生成类型派生队列类型与 `getQueue()`。
  - `apps/workspace/components/QueueGate.tsx`：会话门禁后加载并渲染队列；空队列文案“暂无待接入会话”；未知原因码透传；不渲染完整消息。
  - `apps/workspace/tests/QueueGate.test.tsx`：空队列、FIFO 摘要渲染、401 回登录、网络错误重试、退出。
  - 契约：重新导出 `packages/contracts/openapi.json`、`tests/fixtures/openapi-r0-2.json` 与两个前端的 `api-types.ts`。
  - 追溯：AC-35 已有测试引用，删除 `scripts/trace-baseline.txt` 中的 AC-35 基线行。
- 本次不改变：
  - 领取/接管/回复/关闭/转回（F-07~F-12）；不实现“领取”按钮或状态转换。
  - 认证、session、RBAC 语义（F-05）；不新增角色或权限。
  - 数据模型与迁移：无新表/新列，`db-schema-r0-2.json` 不变。
  - 审计与限速（F-13）；队列读接口不写 `service_audit_events`。
  - 自动分配、WebSocket/SSE、队列分页或位置/SLA（plan Q-3：客户不显示位置，坐席只看等待秒数）。

## 2. 任务级决策

### 2.1 需人类决策

无。队列字段、FIFO、租户隔离与“领取前不返回完整消息”已由 brief AC-35 与 plan 3.3.5 批准；本卡只落实读取实现与展示。

### 2.2 声明的 seam

| ID | 内部接口 | 为什么测试直接驱动它 |
|---|---|---|
| S-1 | `GET /workspace/queue` | FIFO、摘要字段、空队列、401/403 与租户隔离的可观察契约 |
| S-2 | `backend.conversations.workspace_conversations.list_queued_handoffs` | 排序/过滤/批量取末条的唯一查询入口；集成测试经 HTTP 驱动它 |
| S-3 | `backend.conversations.handoffs.redact_text` | 复用既有脱敏实现，队列末条与交接单摘要不出现两套规则 |
| S-4 | `workspace_conversations.utc_now` | 等待秒数需要固定时钟断言，避免真实时间抖动 |
| S-5 | `apps/workspace/lib/queue.ts`（`getQueue`）+ `QueueGate` 渲染 | 前端只按接口顺序展示摘要，不隐藏/补齐字段 |

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 队列响应是裸数组还是对象 | `{items: [...]}` | 与既有响应封套风格一致；后续加 `total`/`as_of` 不需要破坏契约 | 小 |
| D-2 | “脱敏末条”取哪条消息 | 取该会话最后一条 `author_type='customer'` 的消息；系统“排队中，请稍候”不占用摘要 | 队列摘要是给坐席看客户诉求；系统提示对坐席无信息量，且 F-03 已把它写进会话 | 小 |
| D-3 | 等待秒数口径 | `max(0, floor((now - handoff.created_at).total_seconds()))` | 与 plan 3.3.5“等待秒数”一致；夹 0 防时钟回拨出现负数 | 小 |
| D-4 | 同创建时间的排序 | `ORDER BY created_at ASC, id ASC` | plan 明确双键；id 兜底保证测试与演示可重复 | 小 |
| D-5 | 队列是否顺带展示 `handoff.summary` | 不展示 | plan 3.3.5 列的摘要字段已覆盖客户账号/等待/原因/订单数/脱敏末条；`summary` 是交接单快照，不是队列契约 | 小 |
| D-6 | `order_count` 来源 | 固定返回 0，不读 `handoff.context` | plan 3.3.5 明确“order_count=0”；M1 无订单 Tool，读 context 会让脏数据外显 | 小 |
| D-7 | reason 展示 | 接口返回原始码；前端映射中文文案，未知码原样显示 | 契约稳定；新增原因码不需要同步改后端枚举 | 小 |
| D-8 | 队列是否轮询 | 不轮询；打开/重试时拉取一次 | F-06 只要求“打开 `/queue` 看到队列”；3s 轮询留给消息流（F-10），避免无关定时器 | 小 |
| D-9 | 队列读接口是否写库 | 不写库、不提交事务 | 读取不改变交接单归属；“无自动分配”要求读队列不产生副作用 | 小 |
| D-10 | 未领取会话详情是否返回消息 | 继续 404（F-05 语义）；队列响应本身也不含 messages/context | AC-35“领取前不返回完整消息”的两道门禁 | 小 |
| D-11 | 是否需要新迁移 | 不需要 | 队列完全由现有 `service_handoffs`/`service_conversations`/`service_customers`/`service_messages` 派生 | 小 |
| D-12 | 队列上限 | 不加 LIMIT | M1 仅 2 客户/2 坐席；分页不在本切片，提前加 LIMIT 会静默丢单 | 小 |

### 2.4 判定表与失败矩阵
