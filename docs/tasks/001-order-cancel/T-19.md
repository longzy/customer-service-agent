### 4.1 评审返工（不通过 → 修复）

| 问题 | 处理 |
|---|---|
| 启动恢复被硬编码为 1 次重试 | 改为 `settings.max_retries`（默认 3）与 `retry_backoff_seconds` |
| 启动恢复阻塞启动 | 改为 lifespan 内后台任务，退出时最多等待 30s |
| 缺少 SUBMITTING、AC-12 失败、终态不扫描用例 | 已补三类真实 SQL 用例；AC-12 失败转 `MANUAL_REVIEW` |
| lifespan 接线无行为测试 | 新增启动后悬挂任务被恢复为 `MANUAL_REVIEW` 的 TestClient 用例 |
| 恢复身份语义错误 | `account_id` 改为 `startup-recovery`，租户/用户取自任务 |
| 状态集合硬编码 | `list_recoverable` 复用 `RECOVERABLE_STATES` |
| 恢复可能重复提交（二次复审） | 增加 `submit_cancel` 计数断言，恢复只读不写 |
| 默认 3 次重试未被锁住（二次复审） | 新增 lifespan 用例：首次查询失败、默认退避后重试成功到 `ACCEPTED` |
| 退出取消后台任务未 await | 取消后 `asyncio.gather` 等待，再释放 engine |

验证输出：

```text
$ uv run pytest tests/integration/test_startup.py tests/integration/test_cancellation_repository.py -q
8 passed

$ ./scripts/verify.sh
All checks passed
297 passed

$ ./scripts/mutation.sh backend.workflows.cancel
backend.workflows.cancel：killed=276 survived=41 score=87.1%（2026-11-16 T-21 新工具链重跑；旧 86.5% 为旧工具链结果）
```

说明：

- 启动恢复在 lifespan 内使用局部 engine，避免跨事件循环问题。
- 恢复只查询结果、不重复提交；终态任务不会被扫描。
- 启动恢复失败只记录日志，不阻止服务启动。
- 并发冲突记录 warning 并跳过；启动恢复与请求的极端交错仍由版本锁保证不覆盖，但无确定性并发用例，登记为遗留。
