### 2.2 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | Tool 注册方式 | 静态白名单表：`name -> (handler, 是否需要订单归属)`；参数校验读取 `packages/contracts/tools/<name>.json` | 契约是唯一校验源，避免第二套规则 | 小 |
| D-2 | 归属索引来源 | 通过构造参数注入 `OwnershipIndex`；T-05 内提供内存实现，T-06 用同一份夹具填充 | 避免网关依赖具体数据层 | 小 |
| D-3 | 非法输入的错误表达 | 网关层直接拒绝（HTTP 422），不占用领域错误码 | 领域错误码描述业务结果，不描述入参错误 | 小 |
| D-4 | 越权表达 | 统一返回 `NOT_FOUND_OR_UNAUTHORIZED` 错误封套，不区分不存在与无权 | 与 AC-02 一致，避免探测订单存在性 | 小 |
| D-5 | 审计形态 | 每次调用回调 `audit(event)`，事件含工具名、身份、订单号、结果、错误码与 `trace_id`；审计失败按失败关闭 | 持久化留给 T-12 | 小 |

## 4. 证据

### 4.1 首轮返工

首轮实现另建了一套 Pydantic 模型校验，与 T-03 的 JSON Schema 不等价，评审不通过。返工后网关直接以 `packages/contracts/tools/*.json#/$defs/Request` 为唯一校验来源，测试中的“契约等价”不再由测试模型自证。

### 4.2 敏感度检查（人工变异）

为验证安全测试不是摆设，对实现做了三次故意改坏，确认测试会失败：

| 变异 | 结果 |
|---|---|
| 归属只比较租户、忽略用户 | `test_同租户他人订单不可见_AC_02` 失败 |
| 超时一律返回 `DEPENDENCY_TIMEOUT` | `assert 'DEPENDENCY_TIMEOUT' == 'DEPENDENCY_UNAVAILABLE'` 失败 |
| 跳过显式身份字段检查 | 测试仍通过——该场景由契约 `additionalProperties: false` 兜住，显式检查属于纵深防御 |

前两项说明关键安全断言有效；第三项说明“身份字段拒绝”实际由契约保证，测试覆盖的是契约，不是那行防御代码。

### 4.3 返工后的红-绿

| 切片 | 红（实际失败输出） | 绿 |
|---|---|---|
| 非对象参数 | `TypeError: 'NoneType' object is not iterable`（`gateway.py:123`，未审计、未归一） | `isinstance(payload, dict)` 先拒绝，返回 422 并记录 `INVALID_ARGUMENT` |
| 未知异常封套 | 只回 `{"message": "内部错误"}`，缺 code/visible | 改为 `error_envelope(INTERNAL_ERROR)`，测试断言 `visible is False` |
| trace_id 必填 | 缺省时审计写入 `null` | 必填，缺失返回 `INTERNAL_ERROR`，并传入 handler |
