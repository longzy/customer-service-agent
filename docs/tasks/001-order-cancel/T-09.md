## 4. 证据

### 4.1 评审返工（有条件通过 → 修复）

| 问题 | 处理 |
|---|---|
| 模型返回的 `order_id` 可覆盖用户消息中的订单号（高） | 以消息中命中的订单号为准；模型返回未提及的订单号直接 `IntentError`；多候选强制 `order_id=None` |
| 无密钥默认假模型未落地（高） | 新增 `build_model_client`：有密钥用真实客户端；开发/测试无密钥回落假模型；生产缺配置抛 `ModelConfigError` |
| 解析健壮性不足（中） | 非 JSON 响应、工具名错误、参数非字符串统一转 `ModelError`；实现内容 JSON 回落 |
| 真实客户端测试未验证请求（中） | MockTransport 断言方法、路径、Authorization、model、tools、tool_choice；补 500、超时、非 JSON、错误工具名用例 |
| 订单号正则过窄/过宽（中） | 改为边界断言 + 忽略大小写 + 4~12 位，统一大写归一 |
| AC-01 绑定错标（低） | 基座用例改 `_基座豁免`；卡内说明 AC-01 由 T-17/T-10 覆盖 |
| 意图覆盖缺人工（低） | 补 `HUMAN_HANDOFF` 用例；工具枚举由 `Intent` 生成并加一致性测试 |
