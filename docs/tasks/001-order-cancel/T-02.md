## 2. 接口与数据结构

JSON Schema 放在 `packages/contracts/schemas/`，Python 类型由 Schema 生成或与之单向对应，放在 `backend/domain/`。

| 类型 | 关键字段 |
|---|---|
| `OrderSummary` | `order_id`、`item_summary`、`order_status`、`cancelable`、`amount_cents`、`currency`、`created_at` |
| `OrderDetail` | 在 `OrderSummary` 基础上增加 `items[]`、`paid_at`、`shipped_at`（可空） |
| `CancelEligibility` | `eligible`、`reason_code`、`requires_confirmation` |
| `CancellationState` | 十个任务状态的枚举，取值见 `requirements.md` 第 9 节 |
| `ErrorCode` | 五类错误码，见下 |

约定：

- 金额只用整数分（`amount_cents`，`int`），禁止浮点；币种单独字段。
- 时间统一为带 `Z` 的 ISO 8601 UTC 字符串；偏移量形式（如 `+08:00`）与时间戳数字一律拒绝，展示层再转本地时区。
- `paid_at`、`shipped_at` 为“必填但可为 null”：字段存在性是契约的一部分，避免前端把缺失误当可选。
- 标识字段统一为字符串，不加类型前缀推断。

## 3. 状态迁移与失败路径

- 状态与对外表达的映射由后端单一函数提供，前端不得自建文案表；映射表与枚举必须一一对应，缺一即测试失败。
- 错误码分类与属性：

| 类别 | 示例 | 可重试 | 对用户可见 |
|---|---|---|---|
| 业务拒绝 | `ELIGIBILITY_REJECTED`、`OMS_REJECTED` | 否 | 是，附原因 |
| 越权 | `NOT_FOUND_OR_UNAUTHORIZED` | 否 | 是，统一为“查无此单” |
| 依赖不可用 | `DEPENDENCY_UNAVAILABLE`、`DEPENDENCY_TIMEOUT` | 是 | 是，提示稍后重试 |
| 响应非法 | `INVALID_RESPONSE` | 是（有限次） | 是，表达为未知 |
| 内部错误 | `INTERNAL_ERROR` | 视情况 | 否，转人工 |

- `NOT_FOUND_OR_UNAUTHORIZED` 不区分“订单不存在”和“存在但无权”，避免通过错误码探测订单是否存在（对应 AC-02）。

### 7.4 偏差与说明

- JSON Schema 的 `integer` 按规范接受带 `.0` 的表示（如 `399.0`、`1.0`，因为数值本身是整数），而 pydantic 的 `StrictInt` 与 `before-validator` 会拒绝这类输入。这是**有意的不对称**：Schema 是线上传输的最低约束，模型是内部类型的严格边界。受影响的字段是 `amount_cents`、`unit_amount_cents`、`quantity`；`test_strict_types.py` 明确断言模型拒绝 `1.0`。`tests/unit/domain/test_strict_types.py` 开头那句“必须与 Schema 一样”仅适用于 bool 与字符串强转，不适用于整数浮点表示。
- `OrderDetail` 未用 `allOf` 复用 `OrderSummary`：与 `additionalProperties: false` 组合会拒绝新增字段。改为独立定义，并用“required 相等 + 属性相等”的测试守住一致性。
- 突变检查自 T-07 起适用，本任务不运行，也未声称已运行。
