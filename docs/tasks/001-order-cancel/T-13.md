## 1. 改变范围

- 本次改变：
  - `evals/run.py`：解析 pytest JUnit 的 `_AC_XX`，生成 AC 覆盖/通过报告；缺 AC、解析失败、空集返回非零。
  - `tests/integration/test_eval_scenarios.py`：2–3 条脚本化模型多轮场景（查询、歧义澄清、取消意图），测试名带 AC 后缀。
  - `scripts/eval.sh`：以 `set +e` 跑 `test-db.sh`（写 `evals/reports/latest-junit.xml`），无论成败都调用 `run.py`。
  - `scripts/verify.sh`：pytest 带 JUnit，随后复用 JUnit 生成 eval 报告；两类失败都报告。
  - `evals/README.md`、`evals/reports/` 说明与报告。
- 本次不改变：
  - 不引入真实模型/live 评测、不新增依赖、不改 Prompt。
  - 不把 confirm/故障/响应头/日志测试改写为 JSON DSL；这些由既有 pytest 覆盖并在报告中列出。
  - 不改产品代码、数据库迁移与接口。

### 2.4 判定表与失败矩阵

## 4. 证据

红-绿（报告生成器）：先写 `tests/unit/test_eval_report.py`，`evals/run.py` 尚未创建时 6 条全部失败；实现后全绿。
```text
$ uv run pytest tests/unit/test_eval_report.py -q
FileNotFoundError: evals/run.py
6 failed in 0.26s（退出码 1）          # 红
6 passed in 0.15s（退出码 0）          # 绿
```
反向验证（缺 AC）：用 `-k "not AC_15"` 让 AC-15 不进入 JUnit，报告必须失败。
```text
$ ./scripts/test-db.sh -q -k "not AC_15" --junitxml=/tmp/missing-ac15-junit.xml
410 passed, 3 deselected in 6.31s（pytest 退出码 0）
$ uv run python evals/run.py --junit /tmp/missing-ac15-junit.xml --reports-dir /tmp/missing-ac15-reports

AC-15 | 缺失 | 0 | 0 | 0（latest.md，退出码 1）
```
