## 4. 证据

### 4.4 第四轮评审返工

| 问题 | 处理 |
|---|---|
| `GET`/`create` 的 `TaskConflict` 仍 500 | 两个路由都映射 409；补“查询时冲突”用例 |
| `conversation_id` 可由客户端伪造/超长 | 从请求体移除（`extra="forbid"` 返回 422）；关联由 T-15 从可信上下文写入 |
| 乐观锁只用 fake 验证 | 新增真实 Postgres 双 session 冲突用例，第二个写入得到 `TaskConflict` |
| `oms_request_id` 语义不对 | 不再用幂等键冒充；字段留空，真实 OMS 请求 id 归 T-12/T-19 |
| `last_error_code` 覆盖不全 | 恢复查询失败时也记录错误码 |

### 4.3 第三轮评审返工

| 问题 | 处理 |
|---|---|
| `TaskConflict` 未映射，并发冲突 500 | 路由捕获并返回 409；补 API 冲突用例 |
| ORM 模型仍是全局唯一 | 改为 `UniqueConstraint(tenant_id, idempotency_key)`，与迁移 0003 一致 |
| `ACCEPTED -> CANCELLED` 不可达 | 提交受理后与查询时各做一次“只推进不降级”的结果刷新；补 CANCELLED 与查询失败保持用例 |
| 设计字段未写入 | `conversation_id` 由 API 透传；`oms_request_id` 在提交受理时写入 |
| 卡片与记录未收口 | 本节与评审记录同步更新 |
| 测试变慢、旁路构造 | 单测默认退避 0.01s，仅超时用例用 0.4s；恢复用例改用真实提交构造 |

### 4.2 第二轮评审返工

| 问题 | 处理 |
|---|---|
| OMS 返回 `UNKNOWN` 时不重试、不到人工 | `_recover` 把 `UNKNOWN` 当作一次失败尝试，退避后重试，耗尽置 `MANUAL_REVIEW` |
| 提交成功后读失败被降级为人工 | 提交响应为 `ACCEPTED` 时直接落终态，不再依赖结果查询 |
| 无版本锁、联合唯一、设计字段缺失 | 新增 `version` 乐观锁、`(tenant_id, idempotency_key)` 联合唯一、`conversation_id`/`last_error_code`/`oms_request_id` |
| 退避 0.2/0.4/0.8 小于设计 1/2/4s | 默认改为 1.0s，指数递增 |
| 响应契约校验分支无测试 | 补“handler 返回非法 dict → 502 `INVALID_RESPONSE`”用例 |
| 有效期测试恒真、直接改 fake 内部 | 改为假时钟断言 30 分钟；恢复用例通过真实提交与状态构造 |
| `COLLECTING` 从未创建 | 创建任务先落 `COLLECTING`，再转 `AWAITING_CONFIRMATION`/`ELIGIBILITY_REJECTED` |
| 查询路径同步调用网关 | `chat.py` 改用 `asyncio.to_thread` |

### 4.1 评审返工（第一轮）

| 问题 | 处理 |
|---|---|
| 越权/不存在订单返回 500 | 路由捕获 `GatewayError` 并按状态码返回统一封套；补 404 用例 |
| `MANUAL_REVIEW` 不可达、无重试 | 恢复查询按 `max_retries` 退避重试，耗尽置 `MANUAL_REVIEW`；补用例 |
| 网关超时后台写与查询竞争 | 工作流改用 `asyncio.to_thread` 不阻塞事件循环；超时后轮询恢复，实测超时后回到 `ACCEPTED` |
| `SUBMITTING`/`SUBMIT_UNKNOWN` 悬挂 | `get()` 对可恢复状态触发恢复；补“查询触发恢复”用例 |
| 下游非法状态导致 500 | 网关用契约 `Response` 校验，非法响应归 `INVALID_RESPONSE` |
| SQL 仓储零测试 | 新增真实 Postgres 仓储测试（创建/读取/保存/隔离/缺失） |
| 重复确认返回 409 | 已终态直接返回当前结果（幂等）；补用例 |
| `trace_id` 等于 `user_id` | 每个请求生成 UUID，贯穿工作流与网关 |
| AC-06 无放弃入口 | 新增 `POST /cancellation-requests/{id}/abandon`，不写 OMS |
