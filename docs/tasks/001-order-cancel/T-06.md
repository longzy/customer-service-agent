### 2.3 声明的测试 seam

- `MockOms`：读接口、写接口与故障注入的行为边界。
- `FaultEngine`：规则匹配、次数消耗与延迟参数的内部 seam；引擎级用例负责规则语义，服务级用例负责注入效果。
- `services/errors.py`：网关与 Mock OMS 共享的错误类型，保证异常可被正确归类。

### 2.4 与设计清单的差异

- 设计列出“重复响应”故障；M1 用 `unavailable` 覆盖 AC-12 的连续失败，重复响应留待接入真实 OMS 时验证（幂等语义已由 AC-09 覆盖）。
- 取消结果状态由 `set_cancel_result` 推进；订单事实仍以夹具为准，最终一致性由 T-08 Workflow 负责。

### 4.1 评审返工（首轮不通过）

| 问题 | 处理 |
|---|---|
| 幂等键不绑定租户与订单，可跨用户取消 | 写接口增加 `tenant_id`/`user_id`；结果键改为 `(tenant_id, idempotency_key)`；同键不同订单抛 `IdempotencyConflict`；同一订单第二个键抛 `CancelRejected` |
| Mock 异常与网关异常不同类，全部落成 `INTERNAL_ERROR` | 抽出 `services/errors.py` 共享异常；网关显式映射 `DEPENDENCY_TIMEOUT`、`DEPENDENCY_UNAVAILABLE`、`INVALID_RESPONSE`、`OMS_REJECTED`、`NOT_FOUND_OR_UNAUTHORIZED` |
| 管理接口挂在孤立单例上，注入不生效且无输入校验 | `MockOms` 挂到 `app.state`；管理接口读取同一实例；`kind`/`tool`/`state` 用 `Literal` 约束、`times>=1`、非法输入 422 |
| `lost_response` 消耗规则但不生效、`delay` 固定 10ms | 注入逻辑收敛到 `_inject`；读接口把响应丢失视为超时；`delay_ms` 可配置到秒级 |
| 取消结果四态中三态不可达 | 新增 `set_cancel_result` 与管理接口 ``POST /_admin/cancel-result` 可控推进 |
| 归属索引未与网关共享 | 新增 `build_ownership_index(index)`，测试断言夹具与索引一致 |
| 返回浅拷贝污染夹具 | 读取改为 `copy.deepcopy` |
| AC 绑定错标与计数不符 | 测试后缀统一为 AC-01/AC-09/AC-10/AC-11/AC-12，删除未绑定的 AC-02 标注 |
