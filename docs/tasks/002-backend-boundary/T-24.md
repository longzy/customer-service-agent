## 1. 改变范围

- 本卡交付的用户可感知行为：无（内部端口化；HTTP/DB/Tool/Workflow 行为不变）。
- 涉及层：后端适配器、Tool 层、API 装配、测试。

- 本次改变：
  - 新增 `services/adapters/oms/port.py`：`OmsAccess`、`OmsPort`。
  - `MockOms` 迁到 `services/adapters/oms/mock.py` 并改名 `MockOmsAdapter`；`faults.py` 与夹具同迁。
  - `ToolGateway` 改为依赖 `OmsPort`，删除 `OwnershipIndex`；授权调用 `oms.is_visible(access, order_id)`。
  - `build_query_gateway`/`build_cancel_gateway` 改用端口与 `OmsAccess`。
  - `main`/`admin_routes` 使用新 Mock 路径；`verify.sh` 的 prod import 冒烟不再构造 `OwnershipIndex`。
  - 删除旧 `mock_oms` 包（代码已并入 `services/adapters/oms/`）；`import-baseline.txt` 清零。
  - 建立 Mock 契约测试骨架，T-25 接入 Http 后升级为 AC-25。
- 本次不改变：
  - 不改路由、状态码、响应体、Cookie/session、DB schema、Tool 契约、Policy、Workflow 状态机。
  - 不实现 `HttpOmsAdapter`、factory 或生产启动失败（T-25）。
  - 不实现匿名客户访问（M1）；`OmsAccess.verified_order_ids` 只保证类型可承载。

## 2. 任务级决策

### 2.1 需人类决策

无。端口与 Mock 迁移已在 design 第 4、5 节批准。

### 2.2 声明的 seam

| ID | 内部接口 | 为什么测试直接驱动它 |
|---|---|---|
| S-1 | `OmsPort` 的 5 个方法 | 所有 OMS 访问的唯一入口；Mock/Http 契约等价的基础 |
| S-2 | `MockOmsAdapter.is_visible` | 未授权订单不触达业务数据，保持原网关语义 |
| S-3 | `ToolGateway(oms=...)` | 网关授权从本地索引改为端口投影 |
| S-4 | `MockOmsAdapter.faults` | 超时/非法响应/未知结果仍可注入 |

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 是否保留 `MockOms` 别名 | 不保留；测试改名为 `MockOmsAdapter` | 避免两套名字，T-25 统一 | 中 |
| D-2 | `faults.py` 是否合并进 `mock.py` | 保留 `services/adapters/oms/faults.py` | 故障规则独立可测；design 树未禁止 | 小 |
| D-3 | 契约测试组织 | `tests/unit/adapters/test_oms_contract.py`，用 adapter factory；T-25 加 Http 参数与 `_AC_25` | 先建骨架，避免提前声称等价 | 小 |
| D-4 | `OmsAccess` 转换位置 | `tools/query.py`/`tools/cancel.py` 内由 `Identity` 构造 | 网关只依赖端口；不在端口层耦合 Employee | 小 |

### 2.4 判定表与失败矩阵

| AC | 主路径 | 非法输入 | 权限 | 下游故障 | 并发/重复 | 幂等 | 配置门禁 |
|---|---|---|---|---|---|---|---|
| AC-24 | tools/workflows 仅 import `OmsPort`；R2/R6 基线清零 | 直接 import Mock/Http → 检查器失败 | `is_visible` 为 false → `OrderNotFound`，不读订单 | 超时/非法响应/未知状态仍走原错误映射 | 同 key 重复 → 同结果 | 同 key 不同订单 → `IdempotencyConflict` | 不变 |
