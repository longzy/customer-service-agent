## 1. 改变范围

- 本卡交付的用户可感知行为：无（生产接入路径与启动失败语义；默认开发仍走 Mock）。
- 涉及层：适配器、配置、API 装配、测试。

- 本次改变：
  - 新增 `backend/adapters/oms/http.py`：`HttpOmsAdapter`，支持注入 `httpx.Client`。
  - 新增 `backend/adapters/oms/factory.py`：`build_oms(settings)`、`OmsConfigError`、URL 校验。
  - `Settings` 增加 `oms_base_url`；`.env.example` 增加示例。
  - `create_app(settings_override)` 使用 `build_oms`；生产缺配置/非法 URL 启动失败。
  - 契约矩阵接入 Http Adapter，升级为 AC-25。
  - 新增 factory/启动失败测试（AC-26）。
- 本次不改变：
  - 不改路由、响应体、Cookie/session、DB schema、Tool 契约、Policy、Workflow 状态机。
  - 不实现真实 OMS；HTTP 契约仍是设计约定，真实接入前另立 ADR。
  - 不实现匿名客户 `X-Session-Id`（M1）。

## 2. 任务级决策

### 2.1 需人类决策

无。URL 校验与启动失败语义已在 design 5.4、6 批准。

### 2.2 声明的 seam

| ID | 内部接口 | 为什么测试直接驱动它 |
|---|---|---|
| S-1 | `HttpOmsAdapter(client=...)` | 用 `httpx.MockTransport` 覆盖成功/超时/非法响应/404/409，无真实网络 |
| S-2 | `build_oms(settings)` | 配置矩阵的唯一入口 |
| S-3 | `create_app(settings_override)` | 生产缺配置/非法 URL 必须启动失败 |
| S-4 | `Settings.oms_base_url` | URL 合法性与空值判定 |

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | HTTP 客户端同步/异步 | 同步 `httpx.Client` | Tool Gateway 现有线程池调用；与 Mock 一致 | 小 |
| D-2 | 响应校验 | `OrderDetail.model_validate` + 状态白名单 | 非法字段/未知状态归 `DownstreamInvalidResponse` | 小 |
| D-3 | 匿名头 | `user_id=None` 时不发 `X-User-Id`；`X-Session-Id` 留 M1 | R0-2 不实现匿名访问 | 小 |
| D-4 | admin 路由与 Http | 仅当 `app.state.oms` 是 Mock 时挂 admin | 故障注入是 Mock 能力；生产不暴露 | 小 |

### 2.4 判定表与失败矩阵

| AC | 主路径 | 非法输入 | 权限 | 下游故障 | 并发/重复 | 幂等 | 配置门禁 |
|---|---|---|---|---|---|---|---|
| AC-25 | Mock/Http 同一组用例结果一致 | 非 JSON/缺字段 → `DownstreamInvalidResponse` | 404 → `OrderNotFound`，可见性 false | 超时 → `TimeoutError`；连接失败 → `ConnectionError` | 同 key 同订单 → 同 state | 同 key 不同订单 → `IdempotencyConflict` | 不适用 |
| AC-26 | development 空配置 → Mock；合法 URL → Http | 非法 URL → `OmsConfigError` | 不适用 | 不适用 | 不适用 | 不适用 | production 空/空白 → 启动失败 |

## 4. 证据

红-绿（实际）：

```text

```

AC-25 契约矩阵同时跑 Mock 与 Http（`httpx.MockTransport`）：成功、`limit=0`、未授权、超时、连接失败、非法响应、UNKNOWN、重复幂等键、幂等冲突，共 9 类 × 2 Adapter。

AC-26 配置矩阵：

| environment | OMS_BASE_URL | 结果 |
|---|---|---|
| production | 空/空白 | `OmsConfigError` |
| production | 非法 URL（协议、空 host、坏端口、端口越界、IPv6、空白） | `OmsConfigError` |
| production | 合法 URL | `HttpOmsAdapter` |
| development/test | 空 | `MockOmsAdapter` |
| test | 合法 URL | `HttpOmsAdapter` |

`create_app(production, 空 URL)` 抛 `OmsConfigError`；`create_app(test, 空)` 用 Mock；`create_app(test, 合法 URL)` 用 Http。

评审首轮 BT-1（URL 边界）与 BT-2（override 未贯通路由）已修复并补测试；`conftest.py` 在导入 settings 前设 `ENVIRONMENT=test`，使干净检出也能收集测试。
