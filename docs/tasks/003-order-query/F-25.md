# 任务执行卡：F-25 订单访问基座与指定订单查询

- 关联 feature：F-25
- 依据：`docs/specs/003-order-query/requirements.md` AC-50、AC-51；`docs/specs/003-order-query/design.md` 3.1–3.5；[ADR-0006](../../adr/0006-customer-login.md)
- 绑定验收：AC-51（AC-50 的最近订单列表由 F-26 承接）
- 变更级别：T3（订单归属、跨客户隐私、迁移）
- 设计引用：归一口径、摘要字段与失败文案以 plan 3.1/3.2/3.4 为准，本卡只定实现 seam 与确定性规则

## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：客户在聊天里发一个订单号，AI 返回该单的状态、商品、金额与下单时间；不是本人订单或不存在，统一"查无此单"。
- 涉及层：数据库迁移、identity（客户身份补 OMS 客户 ID）、conversations（订单查询模块与消息分支）、DTO、种子脚本、测试；前端由 F-29 承接。

- 本次改变：
  - `migrations/versions/0013_order_query.py`：`service_customers.oms_customer_id VARCHAR(64) NULL` + 部分唯一索引；`service_messages.payload JSON NULL`。
  - `backend/platform/models.py`：两个新字段。
  - `backend/identity/customer_sessions.py`：`Customer.oms_customer_id`，登录与 session 解析都带出。
  - `scripts/seed_demo.py`：`customer_a → user-a1`、`customer_b → user-b1`。
  - `tests/integration/customer_support.py`、`tests/integration/workspace_support.py`：测试种子同样写入映射。
  - `backend/conversations/order_queries.py`：订单号提取、`Identity` 构造、经 `ToolGateway` 查 `get_order`（`asyncio.to_thread`）、摘要白名单、状态文案、模板回复与失败分类。
  - `backend/conversations/customer_chat.py`：关键词检查之后、模型调用之前，正文恰好含 1 个订单号时走订单查询分支；写 `service_ai_events`（`event_type=order_query`）与 AI 消息（含 `payload`）。
  - `backend/conversations/schemas.py`、`customer_http.py`、`workspace_http.py`：`MessagePublic.payload`（可选）；`MessageView` 带 `payload=None` 默认值；工作台消息同样透传。
  - `tests/integration/test_order_query_AC_51.py`：成功、他人、不存在、未绑定、重放、无订单号不查询、取消护栏、OMS 超时。
  - `tests/integration/test_migrations.py`：0013 升级→回滚→再升级。
  - `tests/unit/test_order_queries.py`：订单号提取、摘要、金额/时间格式、文案、未绑定降级。

- 本次不改变：
  - 会话状态机、关键词转人工、模型失败分级与 `decide_model_handoff` 的其余路径。
  - 最近订单列表、多单/半截澄清、闲聊不查（F-26）；连续失败转人工（F-27）；交接单/工作台（F-28）；订单卡片、审计与评测（F-29）。
  - 不新增 HTTP 路由；`packages/contracts/tools/*.json` 不改。

## 2. 任务级决策

### 2.1 需人类决策

无。订单归属、未绑定降级、摘要白名单与 `order_count` 口径已由 brief/plan 批准；本卡只落实现。

### 2.2 声明的 seam

| ID | 内部接口 | 为什么测试直接驱动它 |
|---|---|---|
| S-1 | `POST /customer/messages`（正文含 `ORD-xxxx`） | 走完整消息路径：客户消息落库、AI 消息、`payload`、状态保持 `AI_ACTIVE` |
| S-2 | `service_customers.oms_customer_id` | 归属唯一来源；置空时必须降级为"查无此单"，不得调用 OMS |
| S-3 | `service_messages.payload` | 订单快照，F-29 卡片直接消费；刷新/重放不重新查 OMS |
| S-4 | `tool_executions` | Gateway 调用留痕（工具名、结果、耗时），F-29 断言 |

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 订单号如何识别 | 正文正则 `ORDER_ID_PATTERN`（大小写不敏感，`ORD-\d{4,12}`），不依赖模型输出 | 防幻觉；与关键词优先的确定性护栏一致 | 小 |
| D-2 | 什么时候进查询分支 | 正文恰好 1 个订单号（去重后）；0 个走模型（不变），多个留给 F-26 | F-25 不猜、不选；多单是 AC-52 的澄清范围 | 小 |
| D-3 | 未绑定 `oms_customer_id` | 不调用 Gateway，直接"查无此单"；AI 事件 `status=not_found`（与不存在/他人一致），运维区分靠 F-29 指标/日志 | 安全降级：没有归属就没有数据面；客户侧不可区分 | 小 |
| D-4 | 查询失败（Gateway 5xx/超时/非法） | 回复"订单查询暂时不可用，可以重试，或说「转人工」"；不建单；F-27 再接连续计数 | 本卡先保证不 500、不误建单 | 小 |
| D-5 | 摘要字段 | `order_id`、`item_summary`、`order_status`、`amount_cents`、`currency`、`created_at` + `status_label` + `created_at_local` | plan 3.2 白名单 + 两个派生展示字段；不含 `items`/`paid_at`/`shipped_at` | 小 |
| D-6 | 金额格式 | 整数分拼接 `¥{cents//100}.{cents%100:02d}`，币种非 CNY 时用 `{currency} ` 前缀 | 金额是整数分，避免浮点误差 | 小 |
| D-7 | 时间格式 | 解析 ISO 后转 `Asia/Shanghai`，输出 `YYYY-MM-DD HH:MM` | 客户看到本地时间；测试固定夹具 | 小 |
| D-8 | 文案 | 成功：`你的订单 ORD-10001：无线耳机 × 1，已支付未发货，金额 ¥399.00，下单时间 2026-11-10 10:00。`；查无：`没有查到你名下的这笔订单，请核对订单号，或说「转人工」。` | AC-51 不可区分；AC-54 只陈述 OMS 事实 | 小 |
| D-9 | 订单号大小写 | 统一 `upper()` 后查询与回显 | 夹具大写；避免大小写差异导致查无 | 小 |
| D-10 | 是否调用模型 | 命中恰好 1 个订单号且不含取消/退款等操作词时不调用模型，AI 事件只记 `order_query` | 确定性、省一次模型调用；取消/退款保持 001 的转人工路径（AC-32 回归护栏） | 小 |
| D-11 | 状态文案 | `PAID_UNFULFILLED` 已支付未发货、`FULFILLING` 备货中、`SHIPPED` 已发货、`DELIVERED` 已送达、`CANCELLED` 已取消；未知状态原样回显 | GLOSSARY 的订单状态表；单测逐项断言 | 小 |
