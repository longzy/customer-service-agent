## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：客户在聊天里问"我的订单/最近买了什么"时，AI 列出本人最近 ≤5 笔订单摘要；多个订单号或半截订单号先澄清；闲聊里带"订单"不查询、不建单。
- 涉及层：conversations（订单查询模块、消息分支）、handoffs（订单意图不再一律转人工）、DTO 复用（`payload.orders`）、测试；前端卡片由 F-29 承接。

- 本次改变：
  - `backend/conversations/order_queries.py`：
    - `order_query_kind`（`single`/`multiple`/`partial`/`none`，操作词优先排除）与 `ORDER_QUERY_INTENTS`；
    - `query_recent_orders`（经 `ToolGateway` 调 `list_recent_orders`，`limit=5`，`asyncio.to_thread`）；
    - `build_recent_orders_reply`、`MULTIPLE_ORDERS_REPLY`、`PARTIAL_ORDER_ID_REPLY`、`RECENT_EMPTY_REPLY`；
    - `_failure` 增加 `tool` 归一，供列表失败复用。
  - `backend/conversations/customer_chat.py`：
    - 关键词之后、模型之前：多单 → 澄清；半截 → 澄清；恰好一单 → 现有单笔查询；
    - 模型调用之后：`QUERY_ORDER`/`QUERY_RECENT` 且置信 ≥0.6、无操作词 → 查最近订单（不展示模型回复）；
    - 澄清消息不写订单事件、不带 `payload`。
  - `backend/conversations/handoffs.py`：
    - `OUT_OF_SCOPE_INTENTS` 移除 `QUERY_ORDER`/`QUERY_RECENT`（订单意图由 `ORDER_QUERY_INTENTS` 承接）；
    - 客户正文的超范围词表移除"订单/单号"（闲聊带"订单"不再一律转人工），模型回复护栏保留完整词表（含订单号/订单/单号），防模型编造。
  - 测试：
    - 新增 `tests/integration/test_order_query_AC_50.py`、`test_order_query_AC_52.py`、`test_order_query_AC_54.py`；
    - `tests/unit/test_order_queries.py` 增加最近订单、澄清判定与文案用例；
    - 修订 `tests/unit/test_handoff_triggers.py`、`tests/integration/test_customer_handoff_triggers_AC_32.py` 中"问订单一律转人工"的旧断言（003 brief 已批准修订 001 AC-31/32）；
    - 同步修订 `docs/specs/001-customer-handoff/brief.md` AC-31/32 文本与 `features.md` F-04 描述。
  - 文档：`docs/specs/003-order-query/features.md` F-26 行、`docs/CURRENT.md`、本卡证据。

- 本次不改变：
  - 会话状态机、关键词转人工、模型失败分级（F-24）；订单连续失败转人工（F-27）。
  - 交接单订单上下文与 `order_count`（F-28）；工作台订单区、客户订单卡片、审计 `order.queried`、评测（F-29）。
  - 不新增 HTTP 路由；`packages/contracts/tools/*.json` 不改；迁移不改。

## 2. 任务级决策

### 2.1 需人类决策

无。最近订单口径（≤5）、澄清规则、闲聊不查与文案已由 brief/plan 批准。

### 2.2 声明的 seam

| ID | 内部接口 | 为什么测试直接驱动它 |
|---|---|---|
| S-1 | `POST /customer/messages`（无订单号的订单意图） | 走完整消息路径：客户消息落库、AI 消息、`payload.orders`、状态保持 `AI_ACTIVE` |
| S-2 | `list_recent_orders` Tool（`limit=5`） | 归属与条数由 Gateway 强制；测试断言 OMS 调用次数与顺序 |
| S-3 | `service_ai_events`（`event_type=order_query`、`name=list_recent_orders`） | 混淆矩阵：列表/单笔/澄清各自留痕 |
| S-4 | `service_messages.payload` | 最近订单快照，F-29 卡片直接消费；澄清与闲聊为 `None` |

### 2.3 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 订单分支判定顺序 | 关键词转人工 → 操作词护栏 → 完整订单号（1 单查询、≥2 澄清）→ 半截澄清 → 模型意图 | 确定性规则优先，操作词不能被"订单"意图截走（AC-32 取消路径） | 小 |
| D-2 | 半截订单号识别 | `ORD-` + 1–3 位数字、或 ≥13 位、或 `ORD-` 后无数字；完整订单号不进入半截正则 | 与 `ORDER_ID_PATTERN`（4–12 位）互补，确定性且不猜 | 小 |
| D-3 | 最近订单意图来源 | 模型 `intent=QUERY_ORDER/QUERY_RECENT` 且 `confidence ≥0.6`、正文不含操作词 | plan 3.3"其余走模型意图分类"；低置信保持 001 转人工 | 小 |
| D-4 | 未绑定 `oms_customer_id` 的列表查询 | 不调用 OMS，回"你名下暂时没有订单"（与真无订单不可区分） | 安全降级；单笔仍是"查无此单" | 小 |
| D-5 | 列表成功文案 | `你名下最近 N 笔订单：` + 每行 `序号. 订单号：商品，状态，金额，下单时间` | 只含白名单摘要；固定模板保证事实性（AC-54） | 小 |
| D-6 | 空列表 | `你名下暂时没有订单。需要的话可以说「转人工」。`，事件 `not_found` | plan 3.4；不建单、不转人工 | 小 |
| D-7 | 澄清是否调用 OMS/写事件 | 都不调用、不写 `order_query` 事件、`payload=None` | 澄清不是查询；避免伪造订单快照 | 小 |
| D-8 | 正文超范围词表 | 移除"订单/单号"；模型回复护栏保留完整词表 | 闲聊带"订单"不建单（AC-52）；模型回复涉订单仍拦截（防编造） | 小 |
| D-9 | 订单意图的模型事件 | 模型调用成功仍记 `model/ok`，随后记 `order_query` 事件 | 可观测性：能区分模型分类与工具查询 | 小 |
| D-10 | 列表条数 | `limit=5`，前端只展示 5 条 | plan 3.5；超出不在 M1 范围 | 小 |
| D-11 | 已知操作词 | 复用 F-25 `has_non_query_order_intent` | 取消/退款等不被订单意图截走 | 小 |
