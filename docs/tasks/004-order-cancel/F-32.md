- 模板版本：2026-11-21（DoR §2.1、seam §2.3、判定表 §2.5、DoD §6、发布/回滚 §7）

## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：客户在聊天里说“取消这单/取消订单”即可发起；订单号只作兜底。
- 承接 AC-61 固定短语确认残余：按钮来源已在 F-31 验收，本卡补“确认取消/确定取消/是的，取消”短语路径。
- 涉及层：后端（意图分流/候选/固定短语）、前端聊天、测试

### 1.1 触点（文件 → 改什么）

| 文件 | 改动 |
|---|---|

- 本次改变：
- `customer_chat` 增加取消分支：明确取消意图进入取消流程，不再一律转人工。
- 调整 `OUT_OF_SCOPE_TERMS`/`NON_QUERY_TERMS` 对“取消”的处置；退款等仍转人工。
- 会话内最近一笔唯一订单直接出卡片；无快照或多单列候选；订单号精确定位。
- 固定短语确认（按钮为主、短语辅助），聊天提示“回复确认取消”。
- 消息 `payload` 新增可选 `cancellation`（任务状态/有效期/下一步），只增字段、为空省略；聊天内复用订单卡片的确认态。
- 测试：`tests/unit/test_cancel_intents.py`、`tests/integration/test_order_cancel_AC_63.py`、`apps/chat/tests/ChatCancel.test.tsx`。

- 本次不改变：
- 003 订单查询分支及其 AC-52 语义。
- 列表/确认路由（F-31）。
- 退款/退货/改地址仍转人工。

- 不在本卡范围：模型自主决定取消、任意自然语言代替确认。

### 2.4 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 短语集合 | 确认取消/确定取消/是的，取消（容忍“好的/嗯”前缀与全角标点） | 先窄后扩；避免“取消会怎样”这类询问被当成确认 | 低 |
| D-2 | 候选展示 | 复用订单卡片，点卡片“取消订单”跳 `/orders?cancel=` 复用 F-31 弹层 | 不新增列表页；不替客户选单 | 低 |
| D-3 | 聊天内按钮 | 确认卡片只给“去订单页确认”跳转，确认按钮仍只在订单页弹层 | 避免聊天与订单页两套确认状态机；按钮来源仍是 `BUTTON` | 低 |
| D-4 | 订单摘要来源 | 快照只用于定位；定位后统一 `query_order` 取最新摘要再发起 | 卡片状态与资格判定同源，避免展示旧状态 | 低 |
| D-5 | “取消”词处置 | 从 `OUT_OF_SCOPE_TERMS` 移除；`NON_QUERY_TERMS` 保留 | 取消由本卡承接；003 AC-52“取消不被查询分支截走”不变 | 低 |
| D-6 | 无待确认任务时的确认短语 | 提示引导，不建任务、不转人工、不写 OMS | 客户可能早于卡片发短语；静默创建任务会替客户选单 | 低 |
| D-7 | 取消意图失败分级 | 定位查询失败复用 F-27 的订单失败分级与文案 | 同一会话的订单故障应统一计数与出口，不新增一套 | 低 |
| D-8 | 无快照且名下恰好一笔 | 仍列最近订单候选，由客户点选；只有会话内快照恰好一笔才直出确认卡 | 对齐 AC-63“没带订单号…列候选”的字面；不替客户选单 | 低 |
