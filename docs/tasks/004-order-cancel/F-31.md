## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：客户在列表或聊天订单卡片点“取消订单”，确认后只提交一次；拒绝/过期不提交。
- 涉及层：后端（任务/确认/结果）、迁移、前端 apps/chat、契约

- 测试：`tests/integration/test_order_cancel_AC_60.py`、`tests/integration/test_order_cancel_AC_61.py`、`tests/integration/test_order_cancel_AC_62.py`、`tests/integration/test_migrations.py`（新增 0014 回滚用例）、`apps/chat/tests/CancelCard.test.tsx`。

- 本次不改变：
- 003 订单查询路径与消息 `payload` 结构。
- 聊天取消意图分流、固定短语确认（F-32）。
- 资格原因细化、越权矩阵全量与并发冲突处理（F-33）。

- 交接单取消上下文与工作台取消区（F-35/F-36）。

- 不在本卡范围：退款、已发货拦截、部分取消、坐席代确认、历史订单分页。

### 2.4 实现者自行决定

| ID | 问题 | 决定 | 理由 | 返工代价 |
|---|---|---|---|---|
| D-1 | 确认卡片落点 | 列表项按钮 + 页内弹层；聊天卡片跳 `/orders?cancel=` 复用同一弹层 | FE-DIR-03 禁止 features 互相 import；产品决策要求聊天与列表一致 | 低 |
| D-2 | 结果卡刷新方式 | `POST /customer/cancellations/{id}/refresh` + 列表静默刷新 | 不引入推送；已受理可推进到最终结果；刷新有写副作用，用 POST 保持 GET 只读（ADR-0009） | 低 |
| D-3 | 过期确认的响应 | 200 + `ABANDONED`（不提交），不用 409 | design 3.4 要求“任务结束且不提交”；请求内抛 409 会回滚惰性收尾，与 ADR-0009 请求级 UoW 冲突 | 低 |
| D-4 | 取消审计事件 | 本卡不新增 `service_audit_events` 事件类型；`cancellation.*` 归 F-34/AC-70 | AC-60~62 不要求审计；避免与 F-34 的白名单/字段定义重复 | 低 |
| D-5 | 列表回显范围 | 只回显进行中与待人工任务；已取消由 OMS 状态表达，拒绝/放弃/资格拒绝后按钮恢复 | AC-62 要求按钮恢复；AC-61 的结果由结果卡承载 | 低 |
| D-6 | 确认有效期 | `confirm_timeout_minutes` 默认 1440，`.env.example` 同步；测试注入 0 分钟 | Q-1 已定 24h | 低 |
| D-7 | 同订单并发插入 | 顺序重复点击复用；唯一索引/版本冲突映射 409 `CANCELLATION_CONFLICT`；回读策略归 F-33/AC-66 | 本卡判定表只要求重复点击复用，F-33 负责并发矩阵 | 中 |
