- 绑定验收：AC-67、AC-70

## 1. 改变范围

- 本卡交付的用户可感知行为（只能一个）：提交超时/未知先核实、不重复提交；取消全链路可审计、可追溯。
- 涉及层：后端（Workflow/审计/Trace）、前端（列表刷新入口）、测试、契约

### 1.1 触点（文件 → 改什么）

| 文件 | 改动 |
|---|---|
| `backend/workflows/cancel.py` | 新增 `on_event` 回调与 `_emit`/`_emit_submitted`/`_emit_abandoned`：五类事件在对应状态转换的同一次事务内产出；`abandon` 增 `trigger`（`customer`/`expired`）；提交与恢复补 `cancel_total{state}`/`cancel_unknown_total`/`cancel_submit_latency_ms_total` |
| `backend/conversations/cancellation_audit.py` | 新增事件→`AuditRecord` 映射：实体 `cancellation_request`、任务 id、任务 `trace_id`；只做映射，503 语义留给 HTTP 层 |
| `backend/conversations/customer_cancellations.py` | 新增 `CancellationRuntime`（确认有效期/重试次数/退避/审计出口）；四个服务函数由散参数改为 runtime；过期旧任务 `abandon(trigger="expired")` |
| `backend/conversations/customer_http.py` | `_cancellation_runtime` 装配（配置 + `audit_or_503` 出口）；发起/确认/拒绝/刷新与消息路由统一传 runtime |
| `backend/conversations/customer_chat.py` | 聊天发起与固定短语确认共用同一 runtime：审计与恢复参数不再只在 HTTP 直连路径生效；`CancellationSummary` 载荷补任务 `id` |
| `backend/conversations/schemas.py` | `CancellationSummary` 增可选 `id`（旧消息载荷为空），供列表刷新定位任务 |
| `backend/audit/service.py`、`backend/audit/__init__.py` | 五个 `cancellation.*` 事件常量；metadata 白名单补 `task_id`/`requested_by_*`/`confirmed_by_id`/`confirmation_source`/`state`/`reason_code` |
| `backend/platform/observability.py` | `get_cancel_eligibility` 纳入始终采样：资格/提交/结果三类工具调用都能落 `tool_executions` |
| `apps/chat/features/orders/refreshStates.ts` | 新增收敛状态判定：`SUBMITTING`/`SUBMIT_UNKNOWN`/`ACCEPTED` 且带任务 id 才可刷新 |
| `apps/chat/features/orders/components/OrderListItem.tsx` | 已受理/提交中的列表项提供“刷新结果”按钮（结果卡关闭后的刷新入口） |
| `apps/chat/features/orders/components/CancelDialog.tsx` | 结果卡的刷新判定改用共享模块，避免两处口径漂移 |
| `apps/chat/features/orders/hooks/useCancellation.ts`、`components/OrdersPage.tsx` | `refreshTask`：按任务 id 刷新并把错误落到弹层文案；成功后重读列表 |
| `tests/integration/test_order_cancel_AC_67.py` | 恢复矩阵：三种提交故障、恢复查询超时、并发刷新、终态幂等、列表 id、收敛可解释 |
| `tests/integration/test_order_cancel_AC_70.py` | 五类事件字段/白名单、聊天入口、工具三类同链路、审计失败 503 回滚、不可改删 |
| `tests/unit/workflows/test_cancel.py` | 事件顺序、重复确认不重复写、放弃/过期触发口径 |
| `apps/chat/tests/OrdersPage.test.tsx` | 列表刷新入口：POST refresh 后列表回到最终状态 |
| `packages/contracts/openapi.json`、`apps/*/lib/api-types.ts`、`tests/fixtures/openapi-r0-2.json` | `make gen-contracts` 派生物（`CancellationSummary.id`） |

- 本次改变：
- 接入 `SUBMIT_UNKNOWN` 恢复：最多 3 次退避、幂等键查询、并发保护；重试次数与退避从配置注入请求内 Workflow（此前只在启动恢复生效）。
- 已受理后刷新到 CANCELLED/REJECTED；不把 ACCEPTED 当永久终态。
- 补已受理任务在“我的订单”列表的刷新入口（结果卡关闭后仍可看到最终状态）。
- 审计事件 `cancellation.requested/confirmed/abandoned/submitted/result`；字段与白名单按 design 5.1。
- Tool Gateway 记录资格/提交/结果；同一 `trace_id` 串联。
- 测试：`tests/integration/test_order_cancel_AC_67.py`、`tests/integration/test_order_cancel_AC_70.py`、`tests/unit/workflows/test_cancel.py`、`apps/chat/tests/OrdersPage.test.tsx`。

- 本次不改变：
- 资格/越权（F-33）。
- 交接单取消上下文（F-35）。

- 不在本卡范围：真实 OMS、支付退款、审计归档。
