**Findings（无阻断）**

1. **[建议]** 回复响应 `after_id=本条消息 id`（`backend/api/workspace_routes.py:381`），前端无条件推进游标（`useConversationMessages.ts:53`）。若客户消息在上一轮询后、回复前写入数据库，且 id 更小，下轮轮询会跳过它，刷新后才看到；消息已经持久化，这属于展示边界，影响 AC-37 “消息不丢”（`brief.md:79`）。建议 `after_id` 取会话最新消息 id，或 POST 响应不推进游标。
2. **[建议]** 重放只查 `author_type=="agent"`（`workspace_conversations.py:527`），但唯一约束跨作者为 `(conversation_id, idempotency_key)`（`models.py:238-244`）：同一 key 先被客户用于该会话时，坐席插入会撞唯一约束，返回 500 而不是重放。这是 INV-07（`invariants.md:16`）边界，`CURRENT.md:24` 已把并发幂等登记到 F-13。
3. **[接受为后续]** `plan.md:195` “回复=message+audit”未做，由 F-13（`features.md:27`）承接；`pending_step` 保持原值由 F-12 承接（`F-10.md` D-5/§7）；关闭/转回由 F-11/F-12 承接。均非 F-10 缺失。
4. **[收口待办]** features F-10 仍为 false/—；`CURRENT.md:3/11` 仍是 11-18、682，执行卡 §4 为 11-19、691；trace-baseline AC-37 占位待删；执行卡 §4“实现与证据分两个提交”与 f5d194d 单提交不符。非阻塞。
