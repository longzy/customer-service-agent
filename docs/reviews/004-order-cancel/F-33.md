## 安全评审（T3）

- 评审者：独立上下文（未参与实现），只对本 diff 做威胁模型与越权检查。
- 威胁模型与越权矩阵：客户本人允许、他人/跨租户/不存在统一 404、未登录 401，均有 HTTP 用例；坐席本人接管 + 交接单已核验订单才放行，他人会话/跨租户/未核验/AI 接管一律 `None`；代确认由 `ensure_confirmation_allowed` 拒绝非客户 actor。矩阵实现与 `requirements.md` 附录 C.1、`design.md` 5.1 一致。
- 认证 / 租户 / 归属：客户身份只来自 `csid` 会话；任务读取双过滤 `tenant_id + oms_customer_id`；坐席 scope 同时校验 `tenant_id`、`assigned_employee_id`、`HUMAN_ACTIVE`、交接单 `ACTIVE` 与 `verified_order_ids`；跨租户与不存在的响应体完全相同。
- 幂等、重放与并发：发起插入置于 savepoint，仅识别 `uq_cancellation_active_order` 冲突名（其他 `IntegrityError` 照常抛出），冲突后回读进行中任务，读不到才 409；确认沿用版本条件更新。并发用例断言 `submit_cancel` 合计为 1，不是只看状态码。
- PII、日志与审计：scope 只含 id 与订单号，无 PII；本 diff 无新增日志；审计仍由 workflow 同事务写入，异常回滚不产生半条记录。
- 回滚、监控与依赖/供应链：无迁移、无新依赖；复用 0014 的部分唯一索引；执行卡 §7 已列 404/403 与唯一冲突计数。
- 结论：通过。补充口径：当前**没有**坐席确认入口，`CancellationForbidden` 也尚无 HTTP 映射；F-36 接入工作台路由时必须把该异常映射为 403，否则 AC-65/AC-69 的“代确认 403”只有 seam 证据。初评发现的“恒真闸门”已在 `78cc89d` 移除，未留下虚假控制点。
