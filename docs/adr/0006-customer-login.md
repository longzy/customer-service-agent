# ADR-0006：M1 客户改为登录用户

- 状态：已批准
- 日期：2026-11-16
- 批准：2026-11-16（用户确认：预置客户账号 + 密码登录；订单按账号归属）
- 关联：[产品宪章](../product/charter.md)、[ADR-0005](0005-enterprise-boundary.md)、[客户转人工闭环 brief](../specs/001-customer-handoff/brief.md)
- 取代：ADR-0005 中“客户匿名”与“订单号 + 手机尾号校验”相关决策
- 注（2026-11-18）：M1 切片编号顺延，UI 改版占 002；订单查询/取消/安全硬化改为 003/004/005。下文旧编号按此理解。

## 背景

ADR-0005 选择匿名客户 + 订单号/手机尾号校验，是为了缩小 M1 范围、避免客户账号体系。但该方案在演示与产品表达上有明显问题：

- 多用户场景讲不清：客户 A/B 没有稳定身份，坐席只看到“某个匿名会话”，无法展示“不同客户、各自订单、各自转人工”。
- 转人工上下文弱：坐席接管时缺少客户身份，交接单只能靠会话内容推断。
- 订单号 + 手机尾号是匿名下的补偿机制：多一步校验、额外隐私面，且不是真实企业客服的常见体验。
- 演示时匿名会话与“企业内部客服系统”的定位不一致，容易被理解为消费者 demo。

用户作为产品负责人决定：M1 客户改为登录用户，用预置客户账号演示多用户与转人工。

## 决策

### 1. M1 客户身份

- 客户是**独立 principal**，不是员工角色；员工仍只有 `agent`。
- M1 使用**预置客户账号 + 用户名/密码登录**：种子脚本创建客户账号，不建自助注册。
- M1 不做客户自助注册、找回密码、邮箱/短信验证、OTP、MFA；这些后置。
- 客户 session 24h 绝对过期；登录轮换 token，登出立即撤销；密码用 scrypt 哈希，登录失败限速且不泄露账号存在性。
- 客户账号必须属于一个租户；M1 单租户部署，数据模型保留 `tenant_id`。

### 2. 订单访问

- 订单归属改为**客户账号**：客户只能查询/操作本人账号名下、同租户订单。
- 删除订单号 + 手机尾号校验、`order_access_grants` 与“匿名会话授权”模型。
- 他人订单/跨租户统一 404“查无此单”；未登录 401。
- 客户访问使用 `OmsAccess(tenant_id, user_id=customer.user_id)`；坐席仍使用交接单 `verified_order_ids`，不得把坐席当作订单归属用户。

### 3. 演示账号

- 种子脚本创建至少 2 个客户账号（各自订单）与 2 个坐席账号；README/`.env.example` 记录演示账号，不提交真实密码。
- 登录页是真实用户名/密码表单，不做“选择测试账号”式快捷登录（避免重演 M1-P 的演示级身份）。
- 客户与坐席使用不同登录入口、不同 cookie 名、不同 session 表。

### 4. 数据与保留

- 客户账号长期保留，停用后保留审计；客户 session 24h；消息/交接单 30d；审计 90d。
- 不保存完整手机号；客户账号不要求手机号。
- 客户账号的删除/停用与审计在 M1 后续规格定义；M1 至少支持停用标志。

## 后果

- M1 增加客户登录、账号、密码、session、登录限速与客户登录页；删除订单校验/PII 相关逻辑，净复杂度大致持平或下降。
- 交接单、队列、工作台可以展示客户账号与订单归属，“多用户 + 转人工”可直接演示。
- INV-01/02/03 需要再次修订：客户从“匿名会话”变为“已认证客户账号”。
- ADR-0005 的匿名客户与订单尾号决策被本 ADR 取代；其余企业边界（双前端、仅 OMS Mock、RBAC、模块化单体）继续有效。
- M1 实现按垂直切片：客户转人工闭环（001）、订单查询（002）、取消（003）、安全硬化（004）。
- 生产环境的客户认证后续替换为手机 OTP/SSO；M1 的本地账号是演示/内部验证形态。

## 拒绝的方案

- 继续匿名 + 订单号/手机尾号：多用户与转人工上下文讲不清，且隐私面更大。
- 客户自助注册：M1 增加注册、验证、防滥用、找回密码，范围失控。
- 手机号 + 短信验证码：更真实，但 M1 需接短信服务与成本，不符合当前阶段。
- 登录页“选择客户账号”：仍是演示级身份，不能证明认证/会话/RBAC。

## 复审条件

- 客户自助注册、客户 OTP/SSO 进入排期；
- 真实 OMS/支付/物流接入改变订单归属；
- 多租户或客户跨租户场景进入 M1；
- 合规要求客户账号数据保留/删除策略变化。
