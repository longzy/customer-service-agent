# ADR-0002：M1 选择未发货订单取消

- 状态：已批准
- 日期：2026-11-14
- 批准：2026-11-14（本次会话由用户确认，无保留意见）
- 关联规格：`docs/specs/001-order-cancel/requirements.md`

## 背景

订单取消和退款都能展示 Agent 从问答走向业务执行，但退款额外涉及支付受理、到账、金额和财务状态。需要用一个较小但完整的闭环先验证执行基础设施。

## 决策

M1 锁定“查询本人订单并取消未发货订单”。退款移到 M2。

## 理由

- 取消已覆盖身份、权限、资格、确认、幂等、超时恢复和审计。
- 业务状态比退款到账简单，适合验证 Runtime、Tool 和 Workflow。
- 模拟 OMS 能提供受控的正常和故障场景。
- 避免首版同时承担交易执行与资金一致性问题。

## 后果

- M1 不实现“退款成功”或“退款到账”。
- Mock OMS 需明确支持 `CANCELLED`、`REJECTED` 和未知状态。
- M2 可复用取消流程基础设施，并增加支付侧语义。
