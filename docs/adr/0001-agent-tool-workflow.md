# ADR-0001：采用单主 Agent、领域 Tool 和显式 Workflow

- 状态：拟议
- 日期：2026-11-14
- 关联架构：`docs/architecture/overview.md`

## 背景

电商客服覆盖售前、订单、物流和售后等领域。按业务领域直接拆成多个 Agent 看似直观，但会增加上下文传递、执行路径和错误定位成本。M1 的核心风险不是并行推理能力不足，而是业务操作是否正确、安全、幂等和可恢复。

## 决策

M1 使用一个主 Agent 负责理解、澄清、Tool 规划和用户沟通。领域能力实现为 Tool，高风险业务操作由显式 Workflow 控制。

## 后果

正面：

- Tool 和业务规则可以独立测试。
- 状态和失败节点集中可追踪。
- 降低 Token、通信和调试成本。
- 后续仍可在确有需要时增加子 Agent。

负面：

- 主 Agent 的 Tool 选择需要在评测集上持续验证。
- Workflow 需要显式建模，短期开发量高于自由 Tool Calling。

## 拒绝的方案

- 每个业务域一个 Agent，由 Agent 自由协商：M1 复杂度不必要，可靠性边界不清。
- 单个巨型 Agent 自由执行所有业务操作：无法满足权限、幂等和恢复要求。
