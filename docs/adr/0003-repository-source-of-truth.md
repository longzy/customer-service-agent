# ADR-0003：仓库是 AI Coding 的唯一项目事实源

- 状态：已批准
- 日期：2026-11-14
- 批准：2026-11-14（本次会话由用户确认，无保留意见）

## 背景

AI Coding 会话可能被新建、切换工具、压缩上下文或由不同成员接管。聊天记录不适合作为长期项目状态：工具之间无法保证互通，旧结论也难以识别是否已经失效。

项目需要一个工具无关、可版本化并在每次新会话开始时可以恢复的事实源。

## 决策

仓库是项目状态的唯一权威来源。聊天只用于协作，不承担长期记忆。

长期上下文分为：

- `AGENTS.md`：每次开工的简短路由和硬约束入口。
- `docs/CURRENT.md`：实时阶段、进度、阻塞和下一步。
- `docs/process/README.md`：跨工具协作规范。
- `docs/product/`、`docs/architecture/`、`docs/adr/`、`docs/specs/`：产品、架构、决策和当前规格。
- `docs/handoffs/`：跨会话或跨工具接管时需要的详细交接记录。

其他 AI Coding 工具使用轻量根文件指向同一套文档，不建立第二份项目事实。

## 后果

- 每次有意义的任务完成后，必须更新 `CURRENT.md`。
- 规格、决策或进度发生变化时，以仓库文档而不是聊天结论为准。
- 切换工具后，先恢复项目状态，再开始编码。
- 文档需要维护，但可以避免重复解释、上下文丢失和不同工具得出冲突结论。

## 拒绝的方案

- 依赖某个工具的会话历史作为唯一进度来源。
- 为每个工具维护一套独立项目说明。
- 把所有规则和进度复制进巨大的根指令文件。
