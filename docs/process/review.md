# 评审清单

评审由未参与实现的上下文执行，逐项回答后给出结论。每项只回答"是/否 + 证据"，不写风格意见。

- 适用：执行卡进入 `待评审` 后、标记 `已完成` 前。
- 迁移状态：迁移中（2026-11-16 起，流程与规则以 `docs/process/WORKFLOW.md`、`docs/process/standards.md` 为准；本文保留六问细节）
- 结论三选一：通过、有条件通过（列出必须修复项）、不通过（列出阻断项）。

## 六问

1. **契约等价**：实现是否复用 `packages/contracts` 的 Schema 与类型，而不是另建一套校验或模型？测试是否直接针对契约解析？
2. **测试是否自证**：断言观测的是系统行为，还是测试自己构造的模型？把实现改坏一处，测试会不会失败？
3. **失败路径可达**：下游超时、非法响应、拒绝、越权，是否真的能沿调用链到达出口并映射为正确错误码？有没有只测"能注册/能清理"而不测"生效"的假绿？
4. **证据可复现**：执行卡第 4 节是否含真实失败输出、命令与通过结果？反向验证（故意改坏一条断言确认会红）是否记录？
5. **AC 可追溯**：每个测试名是否指向需求中存在的 AC，或明确标注 `_基座豁免` 并说明理由？执行卡的绑定验收是否与测试一致？
6. **未声明的 seam**：测试是否直接驱动了执行卡未声明的内部接口（引擎、注册表、私有方法）？执行卡 2.3 是否列出了这些 seam？

## 记录要求

- 评审记录写入 `docs/reviews/<spec>/<card>.md`，含日期、轮次、逐项问题与处理。
- 阻断项未修复前不得标记 `已完成`；`check-docs.py` 会在缺少记录时拒绝。
