# TDD 与突变检查规范

- 状态：已批准
- 批准：2026-11-14（本次会话由用户确认）
- 日期：2026-11-14
- 适用：所有包含确定性逻辑的编码任务
- 关联：`docs/process/sdd.md`（阶段门禁）、`docs/process/README.md`（任务闭环）

## 给非实现者的速览

- **seam（接缝）**：测试只从功能对外的入口观察行为，不测内部写法，所以重构不会把测试改红。
- **红-绿**：先写一个会失败的测试（红），再写刚好让它通过的最少代码（绿）；一次只推进一个场景。
- **突变分数**：故意把代码改坏，看测试能不能抓住；抓住的比例就是分数。它检验的是测试本身有没有用。

## 1. 适用范围与例外

必须走测试先行的部分：

- 领域映射函数：状态到用户可见表达、错误码到用户提示。
- Policy Engine：资格判定与原因码。
- Workflow：状态迁移、幂等、超时与恢复。
- Tool Gateway：Schema 校验、授权拒绝、错误归一化。

可以不走 TDD 的部分：

- 纯展示组件与样式调整，但必须有 smoke 测试或组件状态测试。
- 一次性探索脚本，不得进入 `services/` 与 `apps/web/` 的正式路径。
- 生成代码（如由 OpenAPI 生成的类型），由生成器的契约测试覆盖。

## 2. Seam 约定

测试只写在公共边界上，不测私有函数、不 mock 内部协作者。本项目默认 seam：

| Seam | 观测点 | 能抓住 | 抓不住 |
|---|---|---|---|
| 领域映射 | `state -> 用户表达`、`error -> 提示` | 文案与状态错配（AC-16） | 前端渲染细节 |
| Policy Engine | `evaluate(order, user)` 输入输出 | 资格判定错误（AC-04、AC-07） | OMS 实际行为 |
| Workflow | 状态迁移与幂等键 | 重复提交、恢复路径（AC-09~12） | 网络时序细节 |
| Tool Gateway | 输入拒绝与授权 | 越权与非法参数（AC-02、AC-14） | 模型选择质量 |
| HTTP API | 请求与响应 | 契约破坏 | 内部实现结构 |

新增 seam 必须在任务设计卡中写明，否则不写该处测试。

## 3. 红-绿循环

每个循环只推进一个场景：

1. 写一个失败的测试，运行并保留失败输出（红）。
2. 写刚好能通过的最小实现，运行并保留通过输出（绿）。
3. 不提前实现后续场景，不写"顺便以后可能用到"的代码。

证据要求：任务执行卡第 4 节必须记录至少一组红-绿输出（失败断言信息与通过结果），否则该任务不满足完成标准。

禁止 horizontal slicing：不得先把整组测试写完再实现。AI 容易漂移成"批量测试 + 一次性实现"，这类提交应在评审中退回。

## 4. 测试命名与验收绑定

- 测试名使用中文描述行为，并内嵌 AC 编号，例如 `test_已发货订单不可取消_AC_07`（用下划线；连字符不是合法的 Python 标识符）。
- 一个 AC 可以有多个测试，但每个测试必须能追溯到唯一 AC。
- 测试不得通过查询数据库等旁路验证行为，必须经由 seam 观测。

## 5. 突变检查

目的：验证测试真的能抓住错误，而不是覆盖率好看。

- 工具：后端 `mutmut`，前端 `Stryker`（启用增量或缓存）。
- 范围：只跑 `services/workflows`、`services/tools`、`services/api/domain`，不跑全仓。
- 阈值：

| 模块 | 最低突变分数 | 处理 |
|---|---|---|
| Workflow、Tool Gateway | 80% | 未达标不得标记任务完成 |
| Policy Engine、领域映射 | 70% | 未达标需在任务卡说明原因 |
| 前端关键组件 | 60% | 记录趋势 |

- 频率：本地按需运行；每个关键模块任务完成前运行一次。**不进入 pre-commit**，因为它需要数分钟到数十分钟。
- 命令：`scripts/mutation.sh` 在 T-07 随被测模块一起建立；在此之前该命令不存在，不得在文档或提交中声称可用。

## 5.1 seam 验证配方

| seam | 必须有的测试 |
|---|---|
| HTTP 路由 | 走真实路由的 API 测试（状态码、响应体、鉴权） |
| SQL 仓储 | 真实数据库的增删改查、归属隔离、版本冲突 |
| 异步工作流 | 事件循环、超时、恢复、并发冲突 |
| 外部客户端 | transport 失败：超时、非 JSON、错误状态、非法字段 |
| 前端组件 | 渲染 + 交互 + 失败路径，不止快照 |

路由覆盖由 `scripts/check-route-coverage.py` 检查：每个 `@router`/`@app` 路径至少被一个测试引用。

## 6. 与门禁的关系

- 任务完成标准增加两条：红-绿证据已记录；关键模块突变分数达标（自 T-07 起适用）。
- 突变检查结果写入执行卡第 4 节，包含命令、范围与分数。
- 未达标时，实现者必须说明是测试过弱还是存在真实缺口，不得只记录数字。

## 7. 反模式清单

- 先写一整套测试再实现（horizontal slicing）。
- 断言用与实现相同的算法重算期望值（tautological）。
- mock 内部协作者，重构即失败。
- 用覆盖率代替突变分数。
- 把突变检查塞进 pre-commit，拖慢每次提交。
- 让依赖库的弃用警告留在输出里：`pytest` 已将 Starlette 弃用警告升级为失败，出现即修。
