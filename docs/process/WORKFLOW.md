# 标准开发工作流（SDW）

- 状态：已批准
- 批准：2026-11-16（本次会话由用户确认；同日收缩为单份流程文档）
- 适用：本仓库全部变更；人类开发者与 AI Agent 同权
- 关系：[工程标准](standards.md) 定义“什么算合格”；[架构不变量](../architecture/invariants.md) 定义“什么不能破”；[当前状态](../CURRENT.md) 是唯一状态视图
- 旧文档去向见附录 B

## 0. 一页速览

```text
登记分级 → 规格 → 设计 → 任务地图 → 执行卡 → 红绿 → 验证 → 盲评 → 记录发布
```

三句话：**门禁按风险配比；服务端 CI 是唯一硬门禁；状态由产物派生。**

## 1. 原则

| ID | 原则 | 反例 |
|---|---|---|
| P-1 | 风险配比：改错代价决定仪式 | 改注释与改权限模型走同一套流程 |
| P-2 | 机器优先：能判定的不写进人脑 | 靠人记超时配置 |
| P-3 | 单一事实源：一处写入，其余派生 | 4 份手写状态副本 |
| P-4 | 证据可复现：命令 + commit + CI 产物 | 卡内贴“76 passed”，评审写“82 passed” |
| P-5 | 规则预算：新增必须替换或删除 | 同一规则在 3 份文档各写一遍 |

## 2. 变更分级

默认 T1；降级要写理由，升级不许省。

| 级别 | 判据（满足任一即升级） | 产物 | 评审 | 门禁 |
|---|---|---|---|---|
| T0 微改 | 注释、措辞、格式、补丁 | 无卡 | 自审 | G0 + G2 |
| T1 常规 | 单个可观察行为，不动契约/迁移/权限/依赖 | 卡 + 评审 | 1 人独立 | G0–G2 |
| T2 结构性 | 跨层、契约、迁移、新依赖、新模块 | spec/design 更新，必要时 ADR | 2 人 | G0–G3 + 回滚演练 |
| T3 高风险 | 权限、租户、资金、不可逆、模型/Prompt | 全部 + 威胁模型 + 回滚预案 | 独立安全评审 + 业务批准 | G0–G4 + 评测阈值 |

## 3. 阶段与产物

| 阶段 | 动作 | 完成标志 |
|---|---|---|
| S0 登记 | 分配 `NNN-slug`，定级，确认在里程碑内 | 有编号与级别 |
| S1 规格 | 用户故事、EARS、AC、非目标、判定表 | 每条 FR 有 AC；有分支的 AC 有判定表；五问可答；`已批准` |
| S2 设计 | 组件、时序、契约、数据、错误、测试、界面 | 未决项为空；架构取舍有 ADR |
| S3 任务地图 | 垂直切片，能排序、能追 AC | 每条 AC 被引用 |
| S4 执行卡 | 改变范围、人类决策、seam、失败矩阵、验证命令 | 2.1 为空或已答复；绑定 ≤2 AC |
| S5 红-绿 | 一次一个场景，先失败后实现 | 卡第 4 节有红-绿输出 |
| S6 验证 | `./scripts/verify.sh`；关键模块跑突变 | 全绿，无静默跳过 |
| S7 盲评 | 对判定表逐格给证据，不重新解释需求 | 评审记录含结论与逐 AC 表 |
| S8 记录发布 | 勾选任务、更新状态、生成变更日志 | 三方一致，迁移可回滚 |

产物路径：

```text
docs/specs/<NNN>-<slug>/{requirements,design,tasks}.md
docs/tasks/<spec>/T-XX.md          执行卡
docs/reviews/<spec>/T-XX.md        评审记录
docs/adr/                          架构决策
docs/handoffs/                     交接快照（归档，不默认加载）
```

状态：文档 `草案` → `等待评审` → `已批准`；执行卡 `待确认` → `待开工许可` → `待评审` → `已完成`。
检查器覆盖范围以 `scripts/check-docs.py`、`check-status.py`、`trace.py` 为准，不在本文复制清单。

### 3.1 S1.5 可判定性评审

S1 完成前，由未参与写作的上下文只读文档，回答五问：

1. 这条 AC 能否用一个测试或命令判定？
2. 边界值（0、上限、超时、重复）写了吗？
3. 两条规则冲突时谁优先？
4. 失败、超时、重复时用户看到什么？
5. 证据从哪个 seam 观测？

任何一项答“看实现”，退回 S1。输出只有两种：可判定 / 退回并指出哪一问答不上。

### 3.2 触发语

| 你说 | 产出 |
|---|---|
| 澄清 T-XX 的规格 | requirements 判定表 / design 增量，跑五问 |
| 为 T-XX 出执行卡 | `docs/tasks/<spec>/T-XX.md` |
| 执行 T-XX | 代码 + 测试 + 卡第 4 节证据 |
| 评审 T-XX | `docs/reviews/<spec>/T-XX.md` |
| 更新状态 | `tasks.md` 勾选 + `CURRENT.md` 一页事实 |
| 验收 M1 | `evals/` 报告 + 逐 AC 结果 |

## 4. 门禁阶梯

| 层 | 触发 | 时限 | 内容 | 权威 |
|---|---|---|---|---|
| G0 | pre-commit | ≤5s | 格式、lint、密钥、文档/状态/追溯 | 反馈 |
| G1 | pre-push | ≤2min | 单测 + 集成（独立测试库）+ 路由 | 反馈 |
| G2 | PR / push main | ≤10min | G1 + 生产构建 + 依赖审计 + SAST | **唯一硬门禁** |
| G3 | 夜间 | ≤30min | 突变、契约、E2E、flaky | 趋势 |
| G4 | 发布 | 人工 | 迁移/回滚演练、评测阈值、变更说明 | 审批 |

- required checks：`verify`、`frontend-build`。
- 禁止 `--no-verify` 直推；绕过须在 PR 写明原因，24 小时内补跑。

## 5. 状态与追溯

| 事实 | 唯一写入位置 | 派生视图 |
|---|---|---|
| 任务完成 | `tasks.md` 复选框 | `CURRENT.md` |
| 执行契约 | 执行卡 | 评审记录 |
| 评审结论 | 评审记录 | 执行卡状态 |
| 最近验证 | `verify.sh` 生成块 | 无 |

- `CURRENT.md` 只留一页事实，不记录历史过程；`check-status.py` 校验三方一致。
- AC 是追溯骨架：需求定义 → `tasks.md` 引用 → 测试名 `_AC_XX` → 评审逐条结论。
- 未覆盖的 AC 登记在 `scripts/trace-baseline.txt`，只减不增；覆盖后必须删除该行。

## 6. AI 协作

必须：

- 开工复述阶段、已完成、进行中、阻塞、下一步。
- 先写失败测试再实现，保留红-绿输出。
- 结论带证据：文件行号、命令、退出码。
- 文档与代码冲突先报告，不自行选择方便的解释。
- 结束前更新事实源并跑 `verify.sh`。
- 每个 T2 任务的完整 mutation 只跑一次；修复后重跑须在卡里写原因与新增覆盖。

禁止：自审自签、改不变量语义、跳过门禁、编造 AC 或证据、未批准引入依赖或服务、把密钥/真实数据写入仓库或日志。

三项额外证据（AI 代码）：依赖真实存在、许可证可接受、测试能自证（反向验证或突变）。

上下文预算：`AGENTS.md` ≤60 行；`CURRENT.md` ≤80 行；本文 ≤200 行；执行卡 ≤120 行。超限先删内容，不拆第二份。

停止并请求决策：范围外、改状态机/权限/租户/核心架构、引入付费或生产基础设施、与宪章/ADR/验收冲突、处理真实数据或不可逆操作、证据不足且错误代价高、需要降级或跳过 G2。

## 7. 评审

评审两轮：规格轮（S1.5）只看文档，回答第 3.1 节的五问；代码轮（S7）只看判定表与证据。

由未参与实现的上下文执行，逐项“是/否 + 证据”，不写风格意见。

1. 契约等价：是否复用 `packages/contracts`，而不是另建一套？
2. 测试自证：改坏一处实现，测试会不会失败？
3. 失败路径可达：超时、非法响应、越权是否到达出口？
4. 证据可复现：命令、计数、commit 是否齐全？
5. AC 可追溯：每个 AC 有通过或明确未完成结论？
6. 未声明的 seam：是否驱动了卡里没声明的内部接口？

T3 另加：威胁模型、越权矩阵、回滚与灰度、评测通过率。

```text
结论：通过 / 有条件通过 / 不通过
逐 AC：AC-01 通过（证据）| AC-18 未完成（原因 + 承接任务）
阻断项：编号 + 位置 + 必须修复项
```

模板见 [评审记录模板](../templates/review.md)。首轮 24 小时内给出；阻断项修复后补一轮复核。

## 8. 交接与归档

- 触发：切换工具、跨多个长会话、未完成需暂停、关键判断、需要他人接管。
- 内容：目标、已完成、未完成、关键决策与链接、验证结果、阻塞、下一步、涉及文件。
- 文件名 `YYYY-MM-DD-主题.md`；是快照，实时状态仍以 `CURRENT.md` 为准。
- `docs/handoffs/`、`docs/research/` 默认不加载，仅在接管或调研时读。

## 9. 度量与规则预算

指标：前置时间、部署频率、变更失败率、恢复时间、评审轮次、绕过次数、文档漂移数。

回顾每 10 个任务或两周一次，产出必须是“改一条门禁”或“删一条规则”。

规则准入：

1. 同类错误出现第二次才写规则，第一次只修问题。
2. 每条规则写明强制点、owner、失效期。
3. 没有强制点的只能写“建议”，不进默认上下文。
4. 每次回顾最多新增 2 条，且必须删除或合并 1 条。

## 附录 A 测试与突变

| seam | 必须有的测试 |
|---|---|
| HTTP 路由 | 真实路由的状态码、响应体、鉴权 |
| SQL 仓储 | 增删改查、归属隔离、版本冲突 |
| 异步工作流 | 事件循环、超时、恢复、并发冲突 |
| 外部客户端 | 超时、非 JSON、错误状态、非法字段 |
| 前端组件 | 渲染 + 交互 + 失败路径 |

- 红-绿：一次一个场景，保留失败与通过输出；禁止先写整组测试再实现。
- 命名：`test_行为描述_AC_XX`；一个测试只追溯一个 AC；无 AC 的用 `_基座豁免`。
- 突变：Workflow/Tool Gateway ≥80%，Policy/领域映射 ≥70%，前端关键组件 ≥60%（趋势）；只进 G3，不进 pre-commit。
- 反模式：断言复算实现、mock 内部协作者、用覆盖率代替突变、为过测试改不变量语义。
