# 术语表

面向人类与 Agent 的项目术语。分两层：**领域术语**来自需求与业务状态；**工程术语**来自工作流与评测。

## 1. 领域术语

| 术语 | 含义 |
|---|---|
| 客户（Customer） | 企业外部消费者；M1 使用预置账号 + 用户名/密码登录，不是匿名用户 |
| 客户会话（Customer session） | 客户登录后签发的服务端会话；绑定客户账号、消息与订单归属 |
| 坐席（Agent） | 企业内部客服人员；M1 唯一员工角色，本地账号登录工作台 |
| 员工账号 | 内部坐席的登录身份；属于一个租户，由迁移或种子脚本创建 |
| 工作台（Workspace） | 坐席前端；队列、会话、消息、订单、AI 轨迹与交接单 |
| 队列（Queue） | 待领取交接单的集合；状态落 PostgreSQL，不只存内存 |
| 交接单（Handoff） | 转人工时生成的上下文包：摘要、订单、AI 轨迹、待办 |
| 接管（Takeover） | 坐席取得会话控制权，并向客户发送“人工已接入” |
| 订单归属 | 订单属于客户账号；客户只能访问本人同租户订单，坐席按交接单 verified_order_ids 访问 |
| 租户（Tenant） | 数据隔离边界；M1 单企业单租户部署，代码保留 `tenant_id` |
| 订单（Order） | 业务单据；含订单号、商品、状态、金额、支付/发货时间、租户与归属用户 |
| Mock OMS | 按 OMS 契约实现的模拟 Adapter；提供查询、取消资格、提交取消、结果查询与故障注入 |
| 订单状态 | `PAID_UNFULFILLED` 已支付未发货；`FULFILLING` 备货中；`SHIPPED` 已发货；`DELIVERED` 已送达；`CANCELLED` 已取消 |
| 取消申请（CancellationRequest） | 一次取消的业务记录；含订单、状态、幂等键、原因/错误码、trace_id 与版本 |
| 取消资格（Eligibility） | 服务端 Policy 的唯一判定结果；含是否可取消、原因码、是否需要确认 |
| 原因码（Reason code） | 不可取消的原因：`UNFULFILLED`、`FULFILLING`、`SHIPPED`、`DELIVERED`、`CANCELLED` |
| 取消状态 | 见下表；内部状态不得直接暴露给客户 |
| 确认卡片 | 等待客户明确确认的界面；展示订单摘要、状态文案与“确认取消/不取消” |
| 结果文案（ResultCopy） | 由状态唯一生成的“状态标签 + 原因 + 下一步 + 完整回复”；模型不得自创 |
| 幂等键（Idempotency key） | 取消提交的稳定键；同一键重复到达返回同一业务结果，不新建申请 |
| 已受理 / 已取消 / 已退款 | 三个不同结果；`ACCEPTED` 不得表述为已取消或已退款，M1 不产生退款 |

### 取消状态

| 状态 | 含义 |
|---|---|
| `COLLECTING` | 正在确认订单与信息 |
| `AWAITING_CONFIRMATION` | 等待客户明确确认 |
| `ELIGIBILITY_REJECTED` | 不符合条件，禁止提交 |
| `SUBMITTING` | 正在提交取消申请 |
| `SUBMIT_UNKNOWN` | 提交结果未知，等待按幂等键查询 |
| `ACCEPTED` | OMS 已受理，尚未确认最终取消 |
| `CANCELLED` | OMS 已确认订单取消 |
| `REJECTED` | OMS 拒绝取消 |
| `MANUAL_REVIEW` | 超出自动处理边界，转人工 |
| `ABANDONED` | 客户放弃或确认超时，未提交，无 OMS 写调用 |

## 2. 工程术语

| 术语 | 含义 |
|---|---|
| AC | Acceptance Criteria，验收标准；格式 `AC-01`，测试名以 `_AC_01` 结尾 |
| 岗位走查 | 按客户、坐席两条真实岗位路径端到端验收，不以 AC 数量代替 |
| Mock 边界 | 只允许外部业务系统在 Adapter 与测试中被 Mock；身份、会话、队列、审计必须真实 |
| 阻断项 | 必须修完才能评审通过/合并的问题；不修就不能签字 |
| 非阻断遗留 | 已登记、可接受、不影响本次验收的问题；后续任务或触发条件出现时处理 |
| S1.5 | 规格可判定性评审：未参与写作的上下文回答五问，输出“可判定/退回” |
| T0–T3 | 变更分级：T0 微改、T1 常规、T2 结构性、T3 高风险；决定卡、评审人数与门禁 |
| G0–G4 | 门禁阶梯：本地检查、CI、验证、发布等；服务端 CI 是唯一硬门禁 |
| Seam | 测试或调用直接驱动的内部接口；卡里必须声明，评审检查是否被悄悄驱动 |
| 场景评测 | 固定夹具下的端到端/多轮评测；用 pytest JUnit 聚合 + 多轮场景 |
| Trace | 一次请求的完整链路标识；关联消息、工具、状态转换与审计 |

维护：领域术语以 `docs/specs/001-order-cancel/requirements.md` 第 6、9 节为准（M1-P 归档）；企业术语以 [产品宪章](product/charter.md) 与 [ADR-0005](adr/0005-enterprise-boundary.md) 为准；工程术语以 `WORKFLOW.md` 为准。只在首次出现时解释，不重复定义。
