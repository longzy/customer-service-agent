# M1 需求：企业客服核心闭环

- 状态：草案
- 日期：2026-11-16
- 级别：T3（客户登录、员工认证/RBAC、队列权限、订单隐私）
- 依据：[产品宪章](../../product/charter.md)、[路线图](../../roadmap.md)、[ADR-0005](../../adr/0005-enterprise-boundary.md)、[ADR-0006](../../adr/0006-customer-login.md)、[总体架构](../../architecture/overview.md)、[架构不变量](../../architecture/invariants.md)
- 关联：[design.md](design.md)、[tasks.md](tasks.md)
- 已确认决策：D-011 队列领取优先；D-012 会话 24h、消息/交接单 30d、审计 90d；D-013 客户预置账号+密码登录；D-014 订单按客户账号归属
- 已确认演示主线：2 客户 + 2 坐席；客户 A 走完整链路，客户 B 证明隔离与第二条队列
- 已确认会话规则：一个客户同时只有一个未关闭会话；登录恢复；不做历史会话列表
- AC 编号：全局唯一；`001` 使用 01–21，`002` 使用 22–29，本规格使用 30–49

## 1. 目标与演示主线

打通企业客服 M1 的登录客户闭环：

```text
客户 A 登录
  -> 只看到自己的订单
  -> AI 查单/解释；客户要求人工
  -> 交接单进入队列
  -> 坐席 1 登录，队列看到 A（客户账号 + 订单 + AI 轨迹）
  -> 领取 -> 接管 -> 回复 -> 关闭

客户 B 登录
  -> 只看到 B 的订单
  -> 转人工
  -> 坐席 2 领取 B
  -> 证明 A/B 隔离、两个坐席不抢同一会话
```

客户 A 走完整链路；客户 B 证明隔离与第二条队列，不重复取消。M1 员工仍只有 `agent` 角色，2 个坐席只是种子账号。

## 2. 非目标

- 客户自助注册、找回密码、邮箱/短信验证、OTP、MFA；客户账号管理界面。
- 客户画像、会员等级、营销。
- 主管/管理员角色与界面、账号管理、排班、质检、运营后台。
- OIDC/SSO/SCIM。
- 知识库/RAG、FAQ 运营、商品导购。
- 真实 OMS/支付/物流；退款与审批（M2）。
- 全渠道、语音、电话；多 Agent 自主协商；微服务/Kafka/K8s。
- 队列自动分配（D-011，领取优先）。
- 实时推送/WebSocket；M1 客户通过刷新/轮询看到回复与状态。
- 历史会话列表；M1 只恢复当前未关闭会话。

## 3. 用户故事

### US-C1 客户登录、恢复与隔离

作为客户，我用预置账号登录，进入自己的未关闭会话；我的会话和订单不能被其他客户读取。
- 独立测试：正确/错误密码、session 过期、登出、刷新恢复、跨客户 404、Cookie 属性、24h 空闲关闭。
- 验收：AC-30、AC-46、AC-49。

### US-C2 客户 AI 回复、查单与取消

作为客户，我可以让 AI 自动回复；查看本人账号名下订单，并对符合条件的未发货订单发起取消。
- 独立测试：模型正常/超时/不可用、只看到本人订单、跨客户 404、取消确认、重复确认、超时恢复、限速。
- 验收：AC-31、AC-32、AC-33、AC-34、AC-47。

### US-C3 客户转人工

作为客户，我可以在需要时转人工，并看到已进入队列；AI 低置信、高风险、模型不可用或未知结果时也会转人工，而不是死路。
- 独立测试：显式转人工、低置信、高风险、模型不可用、Workflow 未知、无坐席领取。
- 验收：AC-35、AC-36、AC-44。

### US-A1 坐席登录与权限

作为坐席，我用本地账号登录工作台；未登录或非 agent 角色不能访问队列与会话。
- 独立测试：正确/错误密码、session 过期、登出、非 agent、跨租户、越权会话。
- 验收：AC-37、AC-38。

### US-A2 坐席领取与接管

作为坐席，我可以在队列中领取会话、查看客户账号与完整上下文并接管；并发领取只有一个成功。
- 独立测试：FIFO、领取资格、并发领取、接管系统消息、同一会话唯一坐席、第二坐席失败。
- 验收：AC-39、AC-40、AC-41。

### US-A3 坐席回复、取消与关闭

作为坐席，我可以回复客户、在客户确认后发起取消，并关闭会话或转回 AI。
- 独立测试：回复可见、客户确认来源、超时未确认、关闭后拒绝、转回 AI 再低置信。
- 验收：AC-42、AC-43。

### US-S1 安全、审计与隐私

作为系统负责人，我可以证明客户/员工认证、RBAC、跨客户隔离、审计不可篡改、敏感字段脱敏和保留清理都生效。
- 独立测试：越权矩阵、审计失败、脱敏、限速、保留清理。
- 验收：AC-45、AC-46、AC-47、AC-49。

### US-E1 端到端岗位走查

作为评审者，我可以沿客户 A 和客户 B 两条路径走完 M1，不只看 AC 数量。
- 独立测试：AC-48 场景评测；A 全链路、B 隔离、两坐席队列。
- 验收：AC-48。

## 6. 判定表

### 6.1 转人工触发与优先级

| 条件 | 结果 | 优先级 |
|---|---|---|
| 客户显式点击转人工，或意图为 `TRANSFER_TO_HUMAN` | 交接单，原因 `CUSTOMER_REQUEST` | 1 |
| 高风险：`MANUAL_REVIEW`，或同一取消任务 OMS 连续 2 次 `TimeoutError`/`ConnectionError` 且无成功响应 | 交接单，原因 `HIGH_RISK` | 2 |
| Workflow 结果未知（`SUBMIT_UNKNOWN`） | 交接单，原因 `WORKFLOW_UNKNOWN` | 3 |
| 模型超时或不可用（10s 超时） | 交接单，原因 `MODEL_UNAVAILABLE` | 4 |
| AI 置信度 < `AI_HANDOFF_CONFIDENCE_THRESHOLD`（默认 0.6） | 交接单，原因 `LOW_CONFIDENCE` | 5 |
| 无以上条件 | AI 继续自动回复 | — |

同时满足多条取最高优先级。客户显式转人工不得被 AI 降级。低置信阈值由配置注入，测试用 0.59/0.61 边界。`SUBMIT_UNKNOWN` 只归 `WORKFLOW_UNKNOWN`。

### 6.2 客户会话、队列与可见性

| 状态 | 客户可见 | 坐席可见/可操作 | AI 是否回复 |
|---|---|---|---|
| `AI_ACTIVE` | 正常聊天 | 不可见 | 是 |
| `QUEUED` | “已进入队列” | 客户账号+摘要；可领取 | 否 |
| `CLAIMED` | “正在接入人工” | 仅领取者可见全量并接管 | 否 |
| `HUMAN_ACTIVE` | “人工已接入” | 仅接管者回复/取消/关闭/转回 | 否 |
| `CLOSED` | “会话已结束” | 只读 | 否 |

- 一个客户同时只有一个未关闭会话；登录恢复该会话，无则新建；不做历史列表。
- `AI_ACTIVE` 空闲 24h 自动关闭：`last_activity_at` = 最后一条客户或 AI 消息时间；刷新/登录不重置，只有新消息/工具动作更新；`QUEUED/CLAIMED/HUMAN_ACTIVE` 不因 24h 自动关闭。
- 领取资格：`agent` + 同租户 + `QUEUED` + 未被领取；M1 不设坐席并发上限；不做自动分配。
- 同一会话同一时刻只能有一个 `CLAIMED`/`HUMAN_ACTIVE` 坐席。
- `QUEUED/CLAIMED/HUMAN_ACTIVE` 客户消息持久化、不进 AI、不新建交接单；坐席领取后可读。

### 6.3 身份、session 与权限

| 调用方 | 客户聊天接口 | 工作台/队列接口 |
|---|---|---|
| 已登录客户 | 允许本人会话/订单 | 拒绝（403） |
| 未登录 | 401（登录接口除外） | 401 |
| `agent` | 拒绝（工作台身份） | 允许其可领取/已接管会话 |
| 非 `agent` 角色 | 拒绝 | 403 |

- 客户 session：24h 绝对过期（登录时刻起算，刷新不滑动），登录轮换，登出/过期旧 cookie 立即失效；一个客户一个未关闭会话。会话空闲时钟与 session 时钟独立。
- 员工 session：8h 绝对过期，登录轮换撤销旧 session，登出立即失效。
- 跨客户/跨租户/他人会话一律 404，避免存在性泄露。

### 6.4 订单访问

| 场景 | 客户 | 坐席 |
|---|---|---|
| 本人账号、同租户 | 允许查询/取消 | 允许（交接单 `verified_order_ids` 内） |
| 他人订单/跨租户 | 404 “查无此单” | 404 “查无此单” |
| 未登录 | 401 | 401 |
| 未校验 | M1 不存在“会话内订单校验”；登录即账号授权 | 不在交接单集合内 → 404 |
| 完整手机号 | 从不保存 | 不适用 |

坐席访问订单时使用交接单的 `verified_order_ids`，不得把坐席当作订单归属用户。

### 6.5 保留与清理

| 数据 | 保留期 | 清理方式 |
|---|---|---|
| 客户/员工 session | 24h / 8h | 过期即拒绝；定时清理 |
| 消息、交接单 | 所属会话终态（`closed_at`）后 30d | 定时硬删除；未终态/ open 单不删除 |
| 审计事件 | 90d | 定时归档/删除；不含完整正文 |
| 客户账号 | 停用后保留审计 | 停用立即撤销 session、拒绝登录、关闭未关闭会话；M1 不做删除/注销 |
| 完整手机号 | 从不保存 | 客户账号不要求手机号 |

### 6.6 限速

| 动作 | 默认阈值 | 维度 | 超限结果 |
|---|---|---|---|
| 客户消息 | 30/min | 客户 session | 429 `RATE_LIMITED`，不持久化额外消息 |
| 客户登录失败 | 5/15min | 账号 + IP | 429，存在/不存在账号一致 |
| 员工登录失败 | 5/15min | 账号 + IP | 429，存在/不存在账号一致 |

阈值由配置定义；测试注入更低值。429 统一 `{"code":"RATE_LIMITED","retryable":true,"message":"请求过于频繁，请稍后再试"}`；限速先于业务副作用。

### 6.7 冲突优先级

1. 服务端授权 > 前端可见性 > 模型建议。
2. 客户显式转人工 > AI 继续回复。
3. 安全/隐私 > 体验优化。
4. 真实持久化 > 内存状态；队列/会话状态不得只存 Redis。
5. 客户未确认 > 任何取消提交；坐席不得代确认。

### 6.8 会话、取消与审计判定

| 场景 | 结果 |
|---|---|
| 客户登录/重新登录 | 恢复唯一未关闭会话；无则新建；不做历史列表 |
| 客户 session 过期/伪造 | 401；不返回旧消息；重新登录恢复未关闭会话 |
| 客户 A 读客户 B 会话/订单 | 404，不泄露存在性 |
| 坐席发起取消 | 服务端向客户发送带过期时间的确认卡片；客户确认后才提交；客户拒绝或 30min（从确认请求创建起算）未确认 → `ABANDONED`，不提交；坐席代确认 → 403 |
| 审计写失败 | 变更操作 503，业务不提交；只读事件记录告警 |
| 坐席改/删审计 | 404/405；无删除接口；审计只读 |
| 聊天回复“送达” | 持久化后客户刷新/轮询可见；M1 不做推送 |
| 关闭后客户再发 | 409，不创建新消息 |
| 转回 AI 后再次低置信 | 生成新交接单，不复用旧单 |

**脱敏清单**：密码、session/token、完整手机号、完整地址、支付卡、身份证件、完整邮箱。交接单消息与审计正文按此清单替换。

**工作台/客户订单必要字段**：`order_id`、`item_summary`、`order_status`、`cancelable`、`amount_cents`、`currency`、`created_at`、`paid_at`、`shipped_at`；不展示收货地址、完整手机号、支付明细。

**待办口径**：`pending_step` 取 `NONE`、`AWAITING_ORDER_VERIFICATION`、`AWAITING_CUSTOMER_CONFIRMATION`、`AWAITING_OMS_RESULT` 之一；`NONE` 表示无待办。M1 登录客户不需要订单校验，`AWAITING_ORDER_VERIFICATION` 仅保留兼容值，不应出现。

**AI 轨迹口径**：最近 20 条模型/Tool 事件，含 `event_type`、`name`、`status`、`trace_id`，不含请求/响应正文；无事件为空列表。

**Trace**：每个客户会话有稳定 `journey_id`；每个请求有 `trace_id`；消息、Tool、交接单、领取、接管、回复、取消、关闭共享 `journey_id`；登录事件按 `trace_id`+`actor_id` 关联。

|---|---|

## 7. 失败与可观测

- 客户登录失败：统一 401；超限 429；不泄露账号存在性。
- 客户消息失败：可重试提示，不产生半条消息；模型失败按 6.1 转人工。
- 订单查询越权：404；未登录 401；不泄露订单存在性。
- 队列领取冲突：409 `CLAIM_CONFLICT`，不产生双坐席。
- 无坐席：`QUEUED` 持久化，客户看到等待，不返回“已接入”。
- 审计失败：变更操作 503，不提交；只读事件告警。
- 保留清理失败：告警，不阻塞主流程；过期数据不得继续返回。
- 所有关键动作带 `journey_id`/`trace_id`，日志脱敏。

## 9. 安全与隐私目标

- 客户账号：预置账号，密码 scrypt 哈希；不保存完整手机号；登录失败不泄露账号存在性。
- 客户 session：不可猜测 token、`HttpOnly`、`SameSite=Lax`，生产 `Secure`；登录轮换、24h 过期。
- 员工密码只存哈希；M1 使用本地账号，种子脚本创建，不建账号管理界面。
- RBAC、会话归属、订单归属全部服务端校验；跨客户/跨租户 404。
- 审计事件对普通坐席只读；写入口只在服务端；写失败变更操作失败关闭。
- T3 威胁模型、越权矩阵与回滚预案在 S2 design 中补齐。

## 10. 假设与开放问题

**假设**

- M1 单企业单租户部署；数据模型保留 `tenant_id`。
- 2 个客户、2 个坐席种子账号；M1 只有 `agent` 角色。
- 客户预置账号 + 用户名/密码；不做自助注册/找回密码/OTP/MFA。
- 订单按客户账号归属；不保存完整手机号；不做订单号+手机尾号校验。
- 一个客户同时只有一个未关闭会话；登录恢复；不做历史列表。
- 队列领取优先，不做自动分配（D-011）。
- 保留期：会话 24h、消息/交接单 30d、审计 90d（D-012）。
- 低置信阈值默认 0.6；限速默认见 6.6；均由配置注入。
- 取消保留在 M1，实现放在 006 最后；转回 AI/关闭在 005。

**开放问题（S2 前定，不影响 AC 判定）**

- 队列位置/SLA 是否展示给客户；无坐席时的等待文案。
- 模型成本/延迟目标；真实模型评测排期。
- 员工密码策略、种子账号命名。
- 审计归档介质与清理任务频率。

## 11. 威胁模型入口（S2 展开）

S2 design 必须至少覆盖：客户/员工登录固定与伪造、跨客户越权、订单枚举、队列抢占、坐席越权、取消代确认、审计篡改、限速绕过、PII 泄露、内部人员滥用、清理遗漏、CSRF/Origin、IP 伪造。每条给出威胁、控制、验证 seam 与残余风险。
