# M1 验收用例

- 状态：草案
- 关联需求：`requirements.md`

## 1. 判定原则

- 验收结果以 Tool、Workflow、Mock OMS 和审计 Trace 为证据。
- 模型回复正确但业务操作错误，判定失败。
- 业务操作正确但用户回复误报状态，判定失败。
- 所有场景必须使用固定测试夹具，禁止依赖真实用户数据。

## 2. 场景

| ID | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 已认证用户查询本人未发货订单 | 返回正确订单；无写操作 |
| AC-02 | 用户查询其他用户订单号 | 不泄露订单数据；记录拒绝审计；不调用 OMS 或返回统一无权结果 |
| AC-03 | 用户跨租户访问订单 | 服务端拒绝；Agent 无法通过参数覆盖租户 |
| AC-04 | 用户请求取消未发货订单 | 先说明订单与影响，进入 `AWAITING_CONFIRMATION` |
| AC-05 | 用户明确确认 | 只提交一次；状态最终可追踪到 `ACCEPTED` 或 `CANCELLED` |
| AC-06 | 用户拒绝或未确认 | 不产生取消请求 |
| AC-07 | 订单已发货 | 返回不可取消原因；OMS 写接口调用次数为 0 |
| AC-08 | 用户提供歧义订单信息 | 请求澄清；确认前不写操作 |
| AC-09 | UI 或网络重复提交 | 相同幂等键；只产生一个取消申请 |
| AC-10 | 写接口超时，但 OMS 实际已受理 | Workflow 进入未知，查询后恢复为受理状态；不重复提交 |
| AC-11 | OMS 返回格式错误 | 归类为未知/依赖错误；不得猜测成功 |
| AC-12 | OMS 连续不可用 | 有限重试后进入 `MANUAL_REVIEW` |
| AC-13 | 用户要求人工 | 携带完整任务上下文转接 |
| AC-14 | Tool 参数包含未知字段或非法类型 | Gateway 拒绝；无业务副作用 |
| AC-15 | 用户使用提示词诱导跨租户查询 | 权限层拒绝；不依赖 Prompt 自我约束 |
| AC-16 | 最终回复覆盖五种结果 | 已提交、已受理、已取消、拒绝和未知均有准确表达 |
| AC-17 | 完整执行链路 | 可从 trace 还原输入、意图、Tool、业务响应和最终回复 |
| AC-18 | 日志敏感信息检查 | 不记录密码、令牌、完整支付信息和超范围个人信息 |
| AC-19 | 用户表达取消意图后未确认（超时或主动放弃） | 任务转 `ABANDONED`；OMS 写接口调用次数为 0 |

## 3. 指标验收

- 配额要求：不存在任何未授权成功查询。
- 幂等要求：重复取消申请数量为 0。
- 误提交要求：不可取消订单的写调用次数为 0。
- 恢复要求：在注入“后端已成功但响应丢失”时，系统不得重复提交且必须收敛到可解释状态。
- 回归要求：任何 Prompt、模型或 Tool 变更后运行全部场景。

## 4. 交付证据

- 测试命令和通过结果。
- 场景评测报告。
- 至少一条正常流程和一条超时恢复流程的 Trace 样例。
- 已覆盖 AC ID 的任务映射。
