# M1 界面规格：Web Chat

- 状态：草案
- 关联：`requirements.md`、`design.md`、`acceptance.md`
- 设计档位：功能完整的简洁界面。结构参考稿见 `ui-mockup.html`；不做像素级视觉规范，也不做主题与多语言。

## 1. 范围

M1 只有一个入口：单页面 Web Chat，一次只处理一个会话。

非目标：

- 会话列表、历史会话切换和跨会话搜索。
- 多标签页并发操作同一订单。
- 深色模式、移动端原生适配、富文本与附件、消息编辑与撤回。

## 2. 页面结构

自上而下三个固定区域：

| 区域 | 内容 |
|---|---|
| 顶部栏 | 会话标题；右侧常驻“转人工”入口 |
| 消息区 | 可滚动消息列表，用户消息与系统消息视觉可区分；取消相关消息内嵌确认卡片 |
| 输入区 | 文本输入框与发送按钮；等待响应期间禁用 |

确认卡片出现在对应消息内，包含四项必填内容：订单号、商品摘要、当前订单状态、取消影响说明。卡片下方是“确认取消”与“不取消”两个按钮。

页面框架：全局顶栏显示产品名与当前用户，“转人工”位于顶栏右侧；会话内容居中于最大宽度 780px 的列内，两侧留白。M1 没有侧边栏、会话列表、工单列表和坐席后台，这些属于路线图 M4。

## 3. 界面状态与呈现

界面状态由后端返回的任务状态驱动，前端不得自行推断。

| 界面状态 | 触发条件 | 呈现 |
|---|---|---|
| 空白态 | 无消息 | 引导语与一条示例问句 |
| 等待响应 | 消息已发送 | 输入区禁用，显示进行中指示 |
| 输出中 | 模型流式输出 | 逐段追加；不提供“停止生成” |
| 等待确认 | 任务进入 `AWAITING_CONFIRMATION` | 展开确认卡片，两个按钮可用 |
| 已提交、核实中 | 任务进入 `SUBMITTING` 或 `SUBMIT_UNKNOWN` | 提示条“已提交，正在核实受理结果”，确认按钮禁用 |
| 已受理 | 任务进入 `ACCEPTED` | 提示条“已受理，等待最终取消结果” |
| 终态 | `CANCELLED`、`REJECTED`、`ELIGIBILITY_REJECTED`、`ABANDONED` 或 `MANUAL_REVIEW` | 结果条，附下一步说明与人工入口 |

对外文案必须取自 `requirements.md` 第 6 节的“内部状态与用户可见表达”表，界面不得自造措辞。

## 4. 确认交互规则

- 用户必须通过点击“确认取消”完成确认；输入框里的“好的”“可以”不作为确认依据，由 Agent 引导到按钮。
- 点击“确认取消”后按钮立即禁用并进入“已提交、核实中”，避免重复点击产生第二个请求。
- **幂等键由后端生成并随任务持久化，前端不得生成、拼接或缓存幂等键。** 网络重试、刷新后重发都由后端按键去重。
- 点击“不取消”或关闭卡片：界面提示“已取消本次操作”，不产生任何请求，任务按后端规则进入 `ABANDONED`。
- 页面刷新后，前端依据后端返回的数据恢复消息列表与最近一次任务状态，不重开会话；不得凭本地缓存猜测任务状态。

## 5. 错误与未知

- 网络错误：提示“请求未完成”，提供重试；重试沿用同一任务，不新建任务。
- 后端返回未知或依赖异常：界面显示“状态未知，正在核实”，禁止显示成功或失败。
- 任何情况下界面不得在未取得后端明确结果时宣称“已取消”。

## 6. 人工接管

- 顶部栏“转人工”始终可用，包括对话进行中与状态未知时。
- 点击后界面显示“已转人工”，并停止自动回复，避免人工与自动回复同时讲话。
- 转接上下文由后端组装，见 `requirements.md` FR-10；前端不负责拼装。

## 7. 可访问性底线

- 所有操作可用键盘完成，按钮有可见焦点。
- 状态变化用文字表达，不能只靠颜色区分。
- 输入框与按钮有可读标签，供屏幕阅读器识别。

## 8. 与验收用例的对应

| 页面行为 | 对应验收 |
|---|---|
| 确认卡片展示订单与影响，停在等待确认 | AC-04 |
| 确认按钮只产生一次请求 | AC-05、AC-09 |
| 不确认不产生请求 | AC-06 |
| 已发货订单只解释原因，不出现确认按钮 | AC-07 |
| 未知状态措辞不得成成功或失败 | AC-10、AC-11 |
| 五种结果表达正确 | AC-16 |
| 转人工携带上下文 | AC-13 |

## 10. 视觉基调

目标是现代、克制，看起来像正常的客服工作台，而不是演示用的 AI 产品。配色参考 [Radix Colors 的“中性色 + 语义色”分层](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette) 与 [Tailwind 默认色阶](https://tailwindcss.com/docs/colors)。

### 10.1 配色

| 用途 | 取值 | 使用范围 |
|---|---|---|
| 页面背景 | `#F8FAFC` | 大面积 |
| 卡片表面 | `#FFFFFF` | 大面积 |
| 次级填充 | `#F1F5F9` | 用户气泡、禁用态 |
| 描边 | `#E2E8F0`、`#CBD5E1` | 分区与输入框 |
| 正文 | `#0F172A` | — |
| 次要文字 | `#475569` | — |
| 强调 | `#2563EB` | 小于 5%，仅可交互与当前状态 |
| 成功 / 警告 / 危险 | `#059669` / `#B45309` / `#DC2626` | 仅用于状态与危险操作 |

- 骨架全部用中性冷灰，强调色只出现在可交互元素和当前状态上。
- 语义色各自独立、不与强调色混用；危险操作使用红色主按钮，影响说明同色强调。
- 状态用正文加前置小圆点表达，圆点颜色区分结果；不用色条、色块或彩色文字压浅底。
- 页面主色不超过三种，避免暖米色底配墨绿、暗红这类混搭导致画面发浊。

### 10.2 形状与字体

- 圆角 8 至 12px，以 1px 描边区分层次；阴影只用于确认卡片这类需要浮起的元素。
- 使用系统字体栈，不引入远程字体；订单号、金额使用等宽数字。

### 10.3 明确不要

- 渐变背景、玻璃拟态、发光边框、装饰性插画或粒子动画。
- 表情符号、感叹号堆砌和“AI 助手”式口吻。
- 大面积高饱和色块、通篇大圆角加阴影。
