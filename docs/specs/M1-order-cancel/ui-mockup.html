M1 Web Chat 结构参考稿

用途：确认界面的结构与状态，不是视觉设计。所有文案取自 requirements.md 第 6 节的“内部状态与用户可见表达”表。 区域划分与交互规则以 ui.md 为准；本稿与文字冲突时以文字为准。

1. 空白态

无消息
在线客服
您好，我可以帮您查询订单或取消未发货订单。您可以发订单号，也可以直接说“我想取消订单”。
示例：帮我看看 ORD-10001 到哪了
输入消息…

顶部栏的“转人工”在任何状态下都可用。

2. 等待响应

已发送
在线客服
我想取消订单
正在处理…
输入消息…

输入区禁用，避免并发发送打乱任务状态。

3. 等待确认

AWAITING_CONFIRMATION
在线客服
取消订单 ORD-10001
这个订单可以取消，取消后不可恢复。请确认：

确认取消

订单号
ORD-10001
商品
无线耳机 × 1
状态
已支付，未发货
影响
提交后不可撤销，退款按支付渠道处理
输入消息…

四项必填内容缺一不可；口头“好的”不算确认，由 Agent 引导到按钮。

4. 已提交、核实中

SUBMITTING / SUBMIT_UNKNOWN
在线客服
取消订单 ORD-10001
已提交，正在核实受理结果…

确认取消

订单号
ORD-10001
状态
已支付，未发货
输入消息…

按钮立即禁用，防止重复提交；此时不得说“已受理”或“已取消”。

5. 已受理

ACCEPTED
在线客服
取消订单 ORD-10001
已受理，等待最终取消结果。结果确认后我会通知您。
输入消息…

“已受理”与“已取消”是两种表达，不能混用。

6. 终态（已取消 / 不可取消 / 转人工）

CANCELLED / ELIGIBILITY_REJECTED / MANUAL_REVIEW
在线客服
取消订单 ORD-10002
订单已取消。
那 ORD-10003 呢
该订单已发货，不能取消。需要拒收或申请售后吗？
转人工
已转人工，请稍候。人工会看到本次对话与订单上下文。
人工接入中…

终态后确认按钮不再出现；转人工时停止自动回复，避免两边同时说话。
