# 订单查询：客户一句话查到自己的订单，AI 不再一律转人工

> 结构依据：Amazon Working Backwards PR/FAQ；AC 附录为仓库追溯门禁。

- 风险级别：T3（订单归属、跨客户隐私、AI 事实性）
- 客户：终端消费者（客户甲/乙）；客服坐席（坐席 1/2）

## 1. 客户新闻稿（Press Release）

### 标题

客户一句话查到自己的订单，AI 不再一律转人工

### 副标题

客户在聊天里问"我的订单到哪了"，AI 直接回答本人订单；确实查不到或需要人时，才转人工。

### 摘要

M1 转人工闭环里，客户一提到订单就被转人工：AI 不接订单 Tool，交接单的订单数恒为 0。本切片把订单查询接回 AI——客户问"我的订单"时看到本人最近订单，带订单号时看到那一单的状态、商品、金额与下单时间；只有查无此单、越权、OMS 不可用或客户明确要人时，才进入排队。坐席在交接单与工作台里看到同一份订单上下文，不用再追问订单号。

### 问题

客户问订单是最高频的诉求之一。今天这条路径是断的：客户问"我的订单到哪了"，AI 只能转人工；坐席接到会话后还要重新问订单号，客户等待、重复描述。同时 AI 在界面文案里承诺"可以查订单"，实际并不查，信任被消耗。交接单的订单数是写死的 0，坐席看不到客户名下的订单，接管上下文不完整。

### 方案

客户不用按钮，直接在聊天里问：

- 说"我的订单"或"最近买了什么"，AI 列出本人账号名下最近最多 5 笔订单的摘要（订单号、商品、状态、金额、下单时间）。
- 发"ORD-10001"或"查一下这个订单"，AI 回答那一笔；不是本人名下或不存在，统一回"查无此单"，不透露差异。
- 同时提到多个订单号、只说了半截、或只是闲聊里带"订单"二字，AI 先澄清，不猜、不编。
- OMS 超时或异常时，AI 说"订单查询暂不可用，可重试或转人工"，不建交接单；同一会话连续两次查询失败，按既有规则转人工。
- 客户说"转人工"或 AI 判断需要人时，交接单带上最近订单摘要与订单数，坐席在工作台直接看到。

客户看到的仍是聊天，不需要新入口；订单数据只来自 OMS，AI 只复述 OMS 返回的事实。

### 引语（Quote）

> "待补（需真实访谈）"
> —— 客户/坐席，2026-11-20

本切片为 M1 内部闭环验证；引语待补，不作为 G1 门禁。

### 行动号召

无需启用新功能：上线后客户直接在聊天里问订单。M1 仅预置账号，订单数据来自 OMS 适配器（开发环境为 Mock 夹具）；不开放自助注册、代客查单或跨账号查询。

## 2. 常见问题（FAQ）

### 2.1 外部 FAQ（客户/用户会问）

| 问题 | 回答 |
|---|---|
| 谁会用到？ | 客户甲/乙与坐席 1/2；M1 不做主管/管理员。 |
| 怎么用？ | 直接问"我的订单到哪了"或"查一下 ORD-10001"；AI 回答本人订单；需要真人时说"转人工"。 |
| 数据/隐私怎么处理？ | 订单按客户账号归属，只返回本人、同租户订单；他人订单与不存在统一"查无此单"；不展示手机号、支付凭证等 PII；订单查询写审计，但不记正文。 |
| 失败/不可用时怎么办？ | OMS 单次超时/异常先提示重试且不建单；同一会话连续两次失败转人工并说明原因；查无此单不建单、不转人工。 |

### 2.2 内部 FAQ（评审者会问）

| 问题 | 回答 |
|---|---|
| 为什么现在做？ | M1 出口要求"AI 自动回复 + 订单 Tool"；001 收口时 `order_count=0` 已登记待 003 重审；004 取消依赖订单归属与查询能力。 |
| 成功度量是什么？ | AC-50~58 自动化全绿；客户甲/乙走查（甲查乙订单统一"查无此单"）；AI 回复中的订单号/金额/状态与 OMS 一致率 100%（评测集）；交接单 `order_count` 与 OMS 最近订单一致率 100%；查询 P95 ≤ 3s（Mock ≤ 500ms）。 |
| 不做会怎样？ | M1 不能按 roadmap 出口；客户问单仍被转人工，坐席重复追问；交接单缺订单上下文，接管完整率达不到 100%。 |
| 范围与非目标是什么？ | 范围内：本人订单查询（单笔/最近）、AI 回复与澄清、失败分级、交接单订单上下文、工作台订单区、客户侧订单卡片、审计/Trace、评测场景。非目标：取消（004）、退款、物流轨迹、订单修改、代客/跨账号查单、真实 OMS 接入、订单搜索历史、推荐。 |
| 依赖与假设是什么？ | ADR-0006 客户账号与订单归属；OMS 端口与 Mock 夹具已有 `(tenant_id, user_id)` 归属；客户账号与 OMS 客户 ID 的绑定（plan 定）；F-24 失败分级可复用；前端沿用 002 设计系统。 |
| 主要风险与缓解是什么？ | 越权/隐私：服务端归属闸门 + 统一话术 + 审计；模型幻觉：只喂 OMS 摘要字段，回复由确定性模板生成，评测断言无编造；OMS 不稳定：2s 超时 + 提示重试 + 连续失败转人工；旧验收冲突：显式修订 001 AC-31/32 并同步测试；订单快照过期：卡片标注"查询时状态"。 |
| 备选方案是什么？ | ①模型自主 function calling（权限、成本、可观测复杂度高，M1 不用，记为 M3+ 演进）；②固定话术模板（不接订单数据，无法回答，体验差）；③一律转人工（现状，本切片要解决的就是它）；④二次模型调用生成措辞（事实性靠 prompt 约束，成本翻倍，M3 再评估）。 |
| 成本、周期、上线与回滚？ | 5 个 feature（F-25~F-29）；`M1_ENABLED` 控制新行为；迁移只加法（`oms_customer_id` 可空 + 种子回填）；回滚恢复"问订单转人工、`order_count=0`"，不删表。 |

## 附录 A. 验收标准（AC）

> 仓库门禁：`scripts/trace.py` 从本表的 `| AC-` 行读取验收编号；`scripts/check-docs.py` 要求每个 AC 在 `features.md` 出现。
> AC 是 PR/FAQ 之外的追溯附录，不是需求大全；一行一个可观察结果。

| AC | 角色 | 场景 | 期望（可观察） |
|---|---|---|---|
| AC-50 | 客户 | 问"我的订单"/"最近买了什么"（不带订单号） | AI 列出本人账号名下最近 ≤5 笔订单摘要（订单号、商品、状态、金额、下单时间）；无订单时明确说"没有查到订单"并给下一步；不转人工、不建单 |
| AC-51 | 客户 | 消息带订单号（如 `ORD-10001`）；他人订单号；不存在的订单号 | 返回该单状态/商品/金额/下单时间；本人不存在或他人订单统一"查无此单"，两者不可区分；不泄露他人订单信息；不转人工 |
| AC-52 | 客户 | 消息含多个订单号；只有半截订单号；闲聊里带"订单"但无查询意图 | 先澄清或列候选，不猜、不调用 OMS；闲聊不触发查询、不建单；不编造订单信息 |
| AC-53 | 客户 | OMS 超时/异常/返回非法；同一会话连续两次查询失败 | 单次提示"订单查询暂不可用，可重试或转人工"且不建单；连续两次失败转人工并说明原因；订单失败不改变会话状态、不并入模型失败计数 |
| AC-54 | 客户 | AI 回复订单内容 | 回复只含 OMS 返回的摘要字段（订单号、商品、状态文案、金额、下单时间），不编造物流/价格/到货时间；不展示 items 明细、手机号、支付凭证等未授权字段；文案与 GLOSSARY 的订单状态一致 |
| AC-55 | 客户/坐席 | 客户转人工（AI 主动或客户要求） | 交接单带最近订单摘要与 `order_count`（本人最近订单条数，≤5）；无订单时 `order_count=0` 且不写空摘要；工作台详情可见同一份订单上下文 |
| AC-56 | 坐席 | 查看会话详情的订单区；跨租户/他人订单；OMS 异常 | 只显示该客户名下订单；他人/跨租户不可见（沿用 404 不可区分语义）；OMS 异常显示明确提示，不阻塞消息与生命周期操作 |
| AC-57 | 系统 | 每次订单查询（成功/查无/失败） | 有 `tool_executions` 记录（工具名、耗时、结果、错误码，不含 PII）；有 `order.queried` 审计（客户、会话、订单号、结果）；Trace 可按 `trace_id` 关联到会话与审计；审计失败按既有 503 回滚语义 |
| AC-58 | 客户 | 客户聊天中的订单展示 | 订单以结构化卡片展示（查询时快照），含订单号、商品、状态、金额、时间；加载/空/错误态齐全；键盘可达、屏幕阅读器可读；375/900/1200/1440 无溢出 |
