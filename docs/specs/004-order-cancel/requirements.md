## 1. 客户新闻稿（Press Release）

### 标题

客户在“我的订单”里一键取消未发货订单，聊天里也能取消

### 副标题

客户打开“我的订单”，在可取消的订单上点“取消订单”，确认影响后一次提交；也可以在聊天里说“取消这单”，或发订单号作为兜底。

### 摘要

M1 转人工闭环与订单查询已能走通，但“取消订单”仍是死路：客户一说“取消”，系统一律转人工；坐席只能口头安抚，无法在系统里完成取消；旧版取消工作流停留在原型阶段，没有接入客户聊天、坐席工作台与审计。本切片新增客户“我的订单”独立页面——每笔可取消订单直接带“取消订单”按钮；点击后看到订单与影响，确认后由服务端幂等提交。聊天里也能取消，订单号只是兜底而不是主路径。只对未发货订单自动执行，其余状态说明原因并给转人工路径；“已受理、已取消、被拒绝、结果未知”始终可区分。

### 问题

客户要取消订单时，今天只能转人工排队，坐席接管后再手工处理，客户等待且无法自助完成。真实电商的取消主入口是订单列表里的“取消订单”，不是让客户背订单号；生产环境订单号可能有 19–23 位（本切片 Mock 用 `ORD-10001` 这类短号简化），客户既不会背也不会主动输入。当前 M1 只有聊天内查出的订单卡片，没有订单列表入口，也没有任何取消按钮；取消能力全在旧工作流里，与客户会话、工作台、审计脱节。若直接放开写操作，重复提交、代客确认、越权取消都不可控。

### 方案

客户从两个入口取消，订单号只作兜底：

- **主入口：我的订单独立页面。** 客户在聊天顶部点“我的订单”，进入独立的“我的订单”页面（不离开客户 Web Chat 的登录态），查看本人账号名下、同租户的最近订单列表（最多 5 笔，含订单号、商品、状态、金额、下单时间）；页面可返回聊天。可取消的未发货订单直接显示“取消订单”按钮，点击后在页内弹层确认；已发货、备货中、已送达、已取消的订单不显示可提交按钮，并说明原因。
- **对话框入口。** 客户在聊天里说“取消订单”“这单不要了”，系统用会话内最近查询定位；定位不到或存在多单时，列出最近订单候选让客户选，不替客户选。客户发订单号也支持，但只作为兜底。
- **确认后提交。** 点“取消订单”后出现确认卡片：订单号、商品、金额、当前状态、取消影响说明与确认有效期；卡片明确“尚未提交”。客户点“确认取消”或发送固定确认短语后，由 Workflow 只提交一次；客户自己发起和坐席发起走同一提交路径。结果以“已受理/已取消/被拒绝”呈现，“已受理”不表述为“已取消”，M1 不产生退款。
- **不接受确认就结束。** 客户点“不取消”或超过确认有效期未操作，任务结束且不提交；关闭聊天会话不结束等待确认任务，客户仍可在“我的订单”页确认。
- **未知先核实。** 提交超时或结果未知时先按幂等键核实，不重复提交；核实不了就转人工，交接单带取消任务与订单上下文。
- **坐席代发起、客户确认、系统提交。** 坐席在已接管的会话里可以为客户发起取消并说明影响；客户在聊天或订单页点“确认取消”或发送固定确认短语后，由 Workflow 自动提交，坐席不需要也不能再点一次提交。坐席不能代替客户确认；客户未确认时，任务停在等待确认，不会提交。
- **人工接管期间不触发 AI，但客户仍可自助。** 排队/领取/人工中，客户消息不触发 AI 自动取消；客户仍可在“我的订单”页自助取消，任务在工作台可见。

客户看到的仍是聊天 + 一个订单列表；所有写操作由服务端规则与 Workflow 执行，模型只负责理解与解释。

### 行动号召

无需启用新功能：上线后客户从聊天顶部进入独立的“我的订单”页面，或直接在聊天里说“取消这单”。M1 仅支持未发货订单取消；订单列表只展示最近 ≤5 笔，不做历史搜索/分页；订单数据来自 OMS 适配器（开发环境为 Mock 夹具）；不开放退款、自助改地址或跨账号取消；坐席代发起仅限已接管会话且仍需客户确认。

## 2. 常见问题（FAQ）

### 2.1 外部 FAQ（客户/用户会问）

| 问题 | 回答 |
|---|---|
| 谁会用到？ | 客户甲/乙与坐席 1/2；M1 不做主管/管理员。 |
| 怎么用？ | 聊天顶部点“我的订单”进入独立订单页 → 在未发货订单上点“取消订单”→ 页内确认；或直接在聊天里说“取消这单”“取消订单”。发订单号也可以，但不是必须。 |
| 为什么必须输入订单号？ | 不需要。主入口是“我的订单”列表和聊天里的自然表达；订单号可以输入，但只作为兜底。 |
| 数据/隐私怎么处理？ | 订单按客户账号归属，只处理本人、同租户订单；他人/不存在统一“查无此单”；列表只展示白名单摘要字段；确认与结果写审计但不记正文、支付凭证或完整手机号；幂等键只记摘要。 |
| 失败/不可用时怎么办？ | 不可取消说明原因；提交超时先核实、不重复提交；核实不了转人工并在交接单带任务上下文；确认过期视为未提交；关闭聊天会话不结束待确认任务，订单页仍可确认。 |
| 会不会重复扣款/重复取消？ | 同一任务重复确认只提交一次；同一订单已有进行中的取消时不新建；取消结果以 OMS 为准，M1 不退款。 |

### 2.2 内部 FAQ（评审者会问）

| 问题 | 回答 |
|---|---|
| 为什么现在做？ | 用户反馈取消的主入口是订单列表，而不是输入订单号；M1 出口要求“AI 自动回复 + 订单/取消 Tool”；003 已把订单查询接回 AI，但客户侧只有聊天卡片、没有列表，取消仍转人工；旧取消工作流与 Mock OMS 已具备大部分能力，缺口在列表入口、确认入口、企业化越权、工作台与审计。 |
| 成功度量是什么？ | AC-59~72 自动化全绿；客户甲/乙与坐席 1/2 岗位走查通过；未授权取消成功 0；客户未确认提交 0；重复取消申请 0；不可取消订单的 OMS 写调用 0；提交超时恢复后最终状态可解释率 100%；结果文案与状态一致率 100%；取消提交 P95 ≤ 3s（Mock ≤ 500ms，不含模型）。 |
| 不做会怎样？ | M1 不能按 roadmap 出口；客户取消仍需排队，坐席无法闭环；客户只能回到“背订单号”的不现实路径；旧取消工作流继续悬空，越权与重复提交风险没有验收证据。 |
| 范围与非目标是什么？ | 范围内：客户“我的订单”独立页面入口与列表查询、列表/聊天/订单号三种取消发起方式、订单定位与归属、资格判定、确认卡片与过期、幂等提交与超时恢复、结果语义与文案、异常转人工、交接单与工作台取消上下文、审计/Trace、客户与工作台 UI、评测。非目标：退款与到账（M2）、已发货拦截/拒收、改地址/换货/补发、部分取消/部分退款、取消原因采集、批量取消、真实 OMS、主管审批、跨账号/代客取消、历史订单搜索/分页、订单详情页、推荐。 |
| 依赖与假设是什么？ | 001 的客户会话、交接单、工作台、审计与限速；003 的订单查询、订单快照与订单上下文；旧取消领域模型、工具与 Workflow 可复用但需按企业化基线改造；Mock OMS 支持资格、幂等提交、结果查询与故障注入；前端沿用 002 设计系统；M1 不区分支付方式，生产接入按 OMS/平台规则限制。 |
| 主要风险与缓解是什么？ | 新增列表扩大数据面：只返回本人同租户、白名单字段，越权统一查无；列表按钮与服务端资格不一致：按钮只是入口，提交前仍由服务端判定；代确认：确认只接受客户会话，坐席代确认 403，坐席没有提交动作；客户长期不确认：确认过期惰性结束，关闭聊天不放弃等待确认任务；重复提交：幂等键 + 唯一约束 + 任务级状态机；误报状态：结果文案唯一出口 + 子串禁用测试；旧规格冲突：显式修订 001 AC-32 并同步测试；列表与聊天数据不一致：列表/卡片都以 OMS 为准，取消后用同一任务状态刷新。 |
| 备选方案是什么？ | ①只在聊天订单卡片加取消按钮、不做列表：用户明确否，订单列表才是主入口；②文字“确认取消”代替卡片：易误触、不可判定、无法展示影响与有效期，不采用；③坐席代客户确认或直接提交：违反“客户未确认不得提交”（INV-10），不采用；本方案是客户确认后由 Workflow 自动提交；④模型自主调用取消提交：权限与可观测不可控，不采用（M3+ 再评估）；⑤复用旧独立取消 API、不接入聊天/列表：与 001 会话/交接单脱节，不采用；⑥取消继续一律转人工：本切片要解决的正是它。 |
| 成本、周期、上线与回滚？ | 拟 7 个 feature（F-30~F-36，见 `tasks.md`）；`M1_ENABLED` 控制新行为；迁移只加法；回滚恢复“取消一律转人工、旧工作流不产生新任务、隐藏我的订单入口”，不删表、不删已有任务记录。 |

## 3. 产品决策（已定）

以下决策已与用户逐条确认（2026-11-21），全部为“已定”；design 评审时只细化实现，不重新打开产品取舍。

| 决策 | 结论 | 产品影响 |
|---|---|---|
| “我的订单”形态 | 已定：独立页面（如 `/orders`），聊天顶部常驻入口；确认取消用页内弹层，不做抽屉 | 客户多一个页面入口；页面可返回聊天 |
| 列表条数与排序 | 已定：最近 ≤5 笔，按创建时间倒序；不分页、不做历史搜索；找不到时可发订单号兜底 | 列表不是完整订单列表，只覆盖最近订单 |
| 客户确认交互 | 已定：确认卡片按钮为主，固定短语辅助（“确认取消/确定取消/是的，取消”），聊天里提示可回复短语；模糊询问不算确认 | 客户可点按钮或发短语确认；服务端不依赖模型判断 |
| 确认有效期 | 已定：默认 24 小时，可配置；超时任务结束且不提交 | 客户有充足时间确认；测试注入短超时 |
| 坐席发起取消 | 已定（淘宝“帮他退款”式）：坐席可发起并说明影响；客户确认后由 Workflow 自动提交；坐席不二次提交、不能代确认 | 工作台只有发起入口，没有提交/确认按钮 |
| 关闭会话 | 已定：关闭聊天会话不结束等待确认任务，客户仍可在“我的订单”页确认；点“不取消”或超过有效期才结束；提交中/结果未知继续收敛；结果显示订单页 | 关聊天不丢确认入口，也不自动提交 |
| 聊天内订单卡片 | 已定：与列表一致，可取消订单卡片也带“取消订单”按钮；点击复用同一确认弹层 | 聊天卡片与列表行为一致 |
| 同一订单并发任务 | 已定：同一订单同时只有一个进行中的取消任务；重复发起返回当前任务 | 避免同一订单出现两个取消流程 |
| Mock OMS 状态同步 | 已定：取消结果推进为已取消时同步 Mock 的订单状态，使列表/再次查单看到“已取消” | 仅用于验收；生产以 OMS 为准 |

> 评审遗留已决（2026-11-21）：确认有效期 24 小时；关闭聊天不放弃等待确认任务；已受理后继续推进到最终结果；卡片按钮为主、固定短语辅助；列表访问审计 5 分钟去重；M1 不区分支付方式；人工接管期间允许订单页自助取消。`design.md` 第 6 节无未决问题。

### C.3 重复与并发

| 场景 | 结果 |
|---|---|
