## 1. 客户新闻稿（Press Release）

### 标题
客户一句话转人工，坐席在同一会话接管

### 副标题
客户在聊天中发“转人工”，系统排队并交由坐席接管；坐席可回复、关闭或转回 AI。

### 摘要
AI 能处理常见问题，但遇到查单、低置信或客户明确要人时，客户没有可走的人工路径。本切片让客户用自然语言触发转人工，坐席在工作台领取并接管同一会话，客户全程看到排队/接入状态；关闭或转回 AI 后会话可继续。

### 问题
当前 AI 只能处理有限意图。客户问订单、表达不满或明确要“真人”时，会话停在 AI，客户只能反复描述问题或换渠道。坐席侧没有队列、没有上下文、没有接管动作，也无法证明谁在何时处理了什么。

### 方案
客户登录后聊天；发“转人工/人工客服/真人”或模型低置信/超范围/连续失败时，系统创建交接单并让客户看到排队；单次模型超时先提示重试，不直接建单。坐席登录工作台，从队列领取，接管会话，看到客户消息、AI 轨迹和交接单摘要；回复后客户 3 秒内可见。坐席可关闭或转回 AI；客户可随时关闭。客户甲/乙能力一致、互相隔离。

### 引语（Quote）
> “待补（需真实访谈）”
> —— 客户/坐席，2026-11-17

本切片为内部闭环验证；引语待补，不作为 G1 门禁。

### 行动号召
上线后客户无需按钮，直接在聊天中发“转人工”；坐席在工作台队列领取。M1 仅预置账号，不开放自助注册。

## 2. 常见问题（FAQ）

### 2.1 外部 FAQ（客户/用户会问）

| 问题 | 回答 |
|---|---|
| 谁会用到？ | 客户甲/乙与坐席 1/2；M1 不做主管/管理员。 |
| 怎么用？ | 客户登录→聊天→发“转人工”→看排队；坐席登录→队列→领取→接管→回复/关闭/转回。 |
| 数据/隐私怎么处理？ | 只存会话/消息/交接单/AI 事件/审计；AI 轨迹不存 prompt/response 正文与 PII；跨客户/跨租户 404。 |
| 失败/不可用时怎么办？ | 模型单次超时/异常先提示重试并说明可转人工；同一会话连续两次失败或客户要求才自动转人工；审计失败 503 回滚；限速 429；会话关闭后再发 409。 |

### 2.2 内部 FAQ（评审者会问）

| 问题 | 回答 |
|---|---|
| 为什么现在做？ | M1 第一条垂直切片；企业 M1 需要真实身份/会话/队列/审计基座；后续订单/取消切片依赖它。 |
| 成功度量是什么？ | AC-30~39 自动化全绿 + 客户甲/乙人工走查通过 + 审计/限速收口；不设转化率指标（本切片只证明闭环）。 |
| 不做会怎样？ | M1 无法按岗位端到端演示；订单/取消切片没有会话/身份/队列/审计基座。 |
| 范围与非目标是什么？ | 范围内：客户登录/会话、AI 对话、消息触发转人工、坐席登录/队列/领取/接管/回复/关闭/转回、客户甲/乙对等、审计/限速。非目标：订单查询/取消、历史会话、客户注册/OTP/MFA、主管/管理员、自动分配、真实 OMS、WebSocket/SSE、保留清理、全量评测。 |
| 依赖与假设是什么？ | ADR-0006 预置账号+密码；2 客户/2 坐席；PostgreSQL；无 OMS；无 WebSocket；前端两个 Next app。 |
| 主要风险与缓解是什么？ | 登录爆破/会话伪造/跨客户越权/队列抢占/审计篡改/限速绕过；scrypt+dummy hash、token 哈希+轮换、服务端 ownership+404、条件更新+部分唯一索引、同事务审计+只读、PG 桶+可信 IP。T3 威胁模型与越权矩阵见 `design.md`。 |
| 备选方案是什么？ | 按钮转人工 vs 消息触发（选消息：自然语言、少控件）；自动分配 vs 领取（选领取：M1 无 presence/分配规则）；WebSocket vs 3s 轮询（选轮询：先证明闭环）；一个 app vs 两个 Next app（选两个：认证/部署边界）。 |
| 成本、周期、上线与回滚？ | 3 个垂直切片（S-01/02/03）；`M1_ENABLED` 控制新路由与两个 app；迁移只加法；回滚代码不删表，回滚到上一 release；不做保留清理/outbox。 |
