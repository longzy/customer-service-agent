# 架构不变量

- 状态：已批准
- 批准：2026-11-16（随 ADR-0005 与 R0-1 基线批准）

不变量是必须由代码、测试或基础设施保证的规则。提示词可以重复说明，但不能作为唯一执行机制。

| ID | 不变量 | 强制执行位置 |
|---|---|---|
| INV-01 | 每个业务请求必须具有租户、调用主体标识（客户账号或员工用户）和请求关联标识 | API 入口、Tool Gateway、审计 |
| INV-02 | 客户与员工身份、角色与租户都从服务端认证上下文获取，不得由模型或请求正文覆盖 | 认证与授权中间件 |
| INV-03 | 订单查询与操作必须同时校验租户和访问授权：客户按账号归属，坐席按交接单 verified_order_ids；他人/跨租户 404 | Tool/API 服务端 |
| INV-04 | Agent 不得直接访问业务数据库；只能调用注册且授权的 Tool | 进程/模块边界、代码审查 |
| INV-05 | 有副作用的操作必须由显式 Workflow 驱动 | Workflow 与 Tool 写接口 |
| INV-06 | 业务资格由确定性规则判断，模型只能解释结果 | Policy Engine 与测试 |
| INV-07 | 所有写操作必须有幂等键，并在租户范围内唯一 | API 与数据库唯一约束 |
| INV-08 | 写接口超时后先查询状态，禁止无状态盲目重试 | Workflow 与 OMS 契约 |
| INV-09 | “已提交”“已受理”“已取消/完成”必须是不同状态 | 领域模型与契约测试 |
| INV-10 | 客户未确认时不得提交取消申请 | Workflow 状态机 |
| INV-11 | 高风险、歧义、客户明确要求或持续未知状态必须可转人工；转人工必须有队列、领取与关闭闭环，不得是死路 | Workflow、队列与接管接口 |
| INV-12 | 日志、Trace 和评测夹具不得包含真实密钥或完整敏感个人信息 | 日志脱敏与安全测试 |
| INV-13 | 每次模型调用、Tool 调用和状态转换必须可关联到同一执行链路 | OpenTelemetry 与审计 |
| INV-14 | Tool 输入必须经过 Schema 校验，未知字段和非法类型应拒绝 | Tool Gateway |
| INV-15 | 重试和 Agent 循环必须有硬性上限 | Runtime 与 Workflow |
| INV-16 | 任何模型、Prompt 或 Tool 变更都必须运行封存评测集 | CI/评测流程 |
| INV-17 | 工作台接口必须服务端校验员工角色与会话归属，前端隐藏不构成授权 | API 中间件与越权测试 |
| INV-18 | 会话领取与接管必须防重复和并发冲突，同一会话同一时刻只能有一个坐席 | 队列服务与数据库约束 |
| INV-19 | 只有外部业务系统允许 Mock；生产缺少 OMS 配置必须启动失败 | Adapter factory、启动检查与 `check-imports.py` |

## 变更规则

- 新增或修改不变量必须创建 ADR。
- 降低安全或可靠性等级的变更必须明确记录风险和批准人。
- 测试可以验证不变量，但不能为了方便通过而修改不变量的语义。
