# 架构不变量

不变量是必须由代码、测试或基础设施保证的规则。提示词可以重复说明，但不能作为唯一执行机制。

| ID | 不变量 | 强制执行位置 |
|---|---|---|
| INV-01 | 每个业务请求必须具有租户、用户和请求关联标识 | API 入口、Tool Gateway、审计 |
| INV-02 | 用户身份和租户从可信认证上下文获取，不能由模型或请求正文覆盖 | 认证与授权中间件 |
| INV-03 | 订单查询必须同时校验租户、订单归属和数据权限 | Tool/API 服务端 |
| INV-04 | Agent 不得直接访问业务数据库；只能调用注册且授权的 Tool | 进程/模块边界、代码审查 |
| INV-05 | 有副作用的操作必须由显式 Workflow 驱动 | Workflow 与 Tool 写接口 |
| INV-06 | 业务资格由确定性规则判断，模型只能解释结果 | Policy Engine 与测试 |
| INV-07 | 所有写操作必须有幂等键，并在租户范围内唯一 | API 与数据库唯一约束 |
| INV-08 | 写接口超时后先查询状态，禁止无状态盲目重试 | Workflow 与 Mock OMS 契约 |
| INV-09 | “已提交”“已受理”“已取消/完成”必须是不同状态 | 领域模型与契约测试 |
| INV-10 | 用户未确认时不得提交取消申请 | Workflow 状态机 |
| INV-11 | 高风险、歧义和持续未知状态必须可转人工 | Workflow 与人工接管接口 |
| INV-12 | 日志、Trace 和评测夹具不得包含真实密钥或完整敏感个人信息 | 日志脱敏与安全测试 |
| INV-13 | 每次模型调用、Tool 调用和状态转换必须可关联到同一执行链路 | OpenTelemetry 与审计 |
| INV-14 | Tool 输入必须经过 Schema 校验，未知字段和非法类型应拒绝 | Tool Gateway |
| INV-15 | 重试和 Agent 循环必须有硬性上限 | Runtime 与 Workflow |
| INV-16 | 任何模型、Prompt 或 Tool 变更都必须运行封存评测集 | CI/评测流程 |

## 变更规则

- 新增或修改不变量必须创建 ADR。
- 降低安全或可靠性等级的变更必须明确记录风险和批准人。
- 测试可以验证不变量，但不能为了方便通过而修改不变量的语义。
