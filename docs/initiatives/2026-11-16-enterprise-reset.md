## 1. 为什么重置

M1 的 21/21 是**原型验收**，不是企业 MVP 出口。原型按“消费者聊天”实现，导致：

- 页面是消费者聊天，却用员工测试账号登录；
- 转人工只锁输入框，没有队列、坐席、接管和回复；
- 身份、session、坐席、模型 fallback 都是演示级；
- 验收按 AC/接口通过，没有按岗位端到端走通。

根因不是执行，而是产品定义和 Mock 边界错了。继续做 M2 只会放大错位。

## 2. 目标与非目标

**目标**

- 企业内部 AI 客服系统：AI 默认自动回复客户，客户可转人工，人工坐席接管。
- 真实业务代码覆盖：身份、RBAC、会话、队列、分配、接管、回复、审计、持久化。
- 只有 OMS（以及后续支付/物流）允许 Mock；Mock 只存在于适配器和测试。
- 模块化单体，不引入微服务/Kafka/K8s。

**MVP 非目标**

- OIDC/SSO、MFA、SCIM；
- 真实 OMS/支付/物流；
- 退款/审批（M2）；
- 知识库/RAG、质检、全渠道、运营后台（后续）。

## 3. 角色与核心闭环

- **客户**：匿名会话进入 Web Chat，可选昵称；查单/取消前用订单号 + 下单手机号后四位校验；不需要内部账号。
- **AI 助手**：默认自动回复，调用订单/取消 Tool；低置信/客户要求/高风险时转人工。
- **人工坐席**：本地账号登录工作台；领取/被分配会话，查看客户、订单、AI 轨迹，接管并回复。
- **主管**：团队队列、分配、审计（M4）。
- **管理员**：账号、角色、集成配置（M4）。

```text
客户发消息
  -> AI 自动回复/查订单/取消
  -> 客户要求人工
  -> 生成交接单进入队列
  -> 坐席登录、领取会话、查看上下文
  -> 接管并回复
  -> 客户看到“人工已接入”
  -> 关闭或转回 AI
```

## 6. Mock 边界

| 允许 Mock | 不允许 Mock |
|---|---|
| OMS 订单/取消/退款接口 | 员工身份、密码、session、RBAC |
| 支付/物流（后续） | 客户会话、会话/消息、队列、分配、接管 |
| 测试中的模型/外部服务 | 坐席工作台、审计、Trace、持久化 |

Mock 只能出现在 `adapters/` 与测试；业务上下文不得直接 import `mock_oms`。

## 7. 开放问题

1. 分支保护受 GitHub 私有仓库套餐限制；是否升级 Team/公开仓库，另行决定。
2. OIDC 的触发条件：公司 IdP 接入时间、M5 排期。
3. M1 队列等待/SLA 是否展示给客户；由 M1 设计确定。
4. 模型成本/延迟目标；由 M1 设计确定。

## 8. 风险

- 继续在 `services/api` 加功能，会固化 god module；
- 本地认证后续换 OIDC 的迁移成本；
- Mock OMS 与生产适配器契约漂移；
- 工作台/队列是主路径，不能当“后续优化”；
- 分支保护未强制，CI 仍靠纪律。
